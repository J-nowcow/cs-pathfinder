## 사이클 규칙

1. **이 파일을 먼저 읽는다.** 맨 위 미완료 항목을 고른다. 앞 항목이 막혀 있으면 건너뛰되 왜 막혔는지 적는다
2. **한 사이클에 하나.** 반쯤 한 것을 남기지 않는다
3. **재는 것부터.** 고치기 전에 지금 값을 재고, 고친 뒤 다시 잰다. 안 쟀으면 좋아졌다고 쓰지 않는다
4. **되돌림을 잡는 시험.** 코드를 고쳤으면 시험이 있어야 하고, **지웠을 때 실패하는지 확인한다**
5. 끝내면 이 파일에 `[x]`와 잰 숫자 한 줄

## 검증 게이트

파일로 받고 종료 코드를 직접 본다. `| tail`은 파이프 종료 코드가 tail의 것이라 **실패를 감춘다.**

```
npm run typecheck > /tmp/tc.log 2>&1; echo "tc=$?"
npx vitest run    > /tmp/vt.log 2>&1; echo "vt=$?"
npm run build     > /tmp/bd.log 2>&1; echo "bd=$?"
```

**하나라도 0이 아니면 푸시하지 않는다.**

## 조심할 것

- **"없다"는 보고는 코드로 확인하기 전까지 전제로 쓰지 않는다**
- **문자열 유사도로 중복 규모를 판단하지 않는다.** 6.2배 틀린 적이 있다
- **검사기를 만들면 프롬프트에도 넣는다.** 안 그러면 아무도 안 부른다
- **표 비율은 지표가 아니다.** 2층 stack이 표로 옮겨가면 비율이 오히려 오른다. 지표는 오형 건수다
- **`block`을 남발하면 내용을 빼서 통과하는 답이 이긴다.** 지적 수가 줄기만 하면 재시도가 채택되기 때문이다
- **`rtk`가 파이프 출력을 자른다.** curl 결과는 파일로 받아서 읽는다
- React는 `#{n}`을 `#<!-- -->3`으로 낸다. 순진한 grep은 못 찾는다
- 할당량 키가 IP인데(`quota/key.ts`) 투표 키는 국내 캐리어 NAT 때문에 IP를 일부러 안 쓴다(`vote/identity.ts`). `QUOTA_ANON_DAILY`를 정상값으로 되돌리면 NAT 뒤 여러 명이 한 사람 몫을 나눈다

## 알람

사용자가 Remote Control을 켜뒀다. **사람이 정해야 하는 것이 생기면 알람을 보내되, 답을 기다리지 않고 계속 판다.** 스스로 정하고 근거를 남긴 뒤, 사용자가 뒤집을 수 있게 되돌리는 법을 적는다.
