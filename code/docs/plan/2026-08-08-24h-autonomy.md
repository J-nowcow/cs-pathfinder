### ⚠️ 본문을 고칠 때 반드시 읽을 것

**정적 파일이 진짜 출처다.** `bootstrap.ts`가 `data/*.ts`에서 `qnode.body`를 덮어쓴다. **DB만 고치면 조용히 되돌아간다** — 배포를 안 해도, 살아 있는 사이트에 요청 하나만 들어오면 그때 복구된다.

실제로 당했다. 34편을 고쳤는데 넷이 원래대로 돌아가 있었다. 그 넷은 `generated-nodes.ts`가 아니라 `example-nodes.ts`에 살던 것이었다.

본문이 사는 곳이 **넷**이다 — `generated-nodes.ts`(대부분) · `example-nodes.ts`(손으로 쓴 30개) · `authored-nodes.ts` · `pending-nodes.ts`. 게다가 **담는 방식이 다르다.**

- `generated-nodes.ts` — 한 줄짜리 문자열에 `\n`을 박아 넣는다
- `example-nodes.ts` — `[ '줄', '줄' ].join('\n')` 줄 배열이다

`scripts/lib/patch-data.ts`가 둘 다 다루고, 못 찾으면 **큰 소리로 알린다**. 새 도구를 만들 때 반드시 이것을 거쳐라. 고친 뒤에는 `docs/audit/_bodies-before-*.json`의 원본과 DB를 대조해 되돌아갔는지 확인한다.

## 검증 게이트

파일로 받고 종료 코드를 직접 본다. `| tail`은 파이프 종료 코드가 tail의 것이라 **실패를 감춘다.**

```
npm run typecheck > /tmp/tc.log 2>&1; echo "tc=$?"
npx vitest run    > /tmp/vt.log 2>&1; echo "vt=$?"
npm run build     > /tmp/bd.log 2>&1; echo "bd=$?"
```

**하나라도 0이 아니면 푸시하지 않는다.**

- **카카오톡 실제 발송·채널 개설·사업자 정보 입력**
- 결제·구독·도메인 구입
- 운영 DB의 파괴적 변경 — `drop`·`truncate`·조건 없는 `delete`. 스키마는 **추가만**
- 파일·브랜치 삭제 (백로그가 지목한 `/zz-proto`·`/zz-svg` 제거는 예외)
- `main` 히스토리 고쳐쓰기 (`push --force`)
- Gemini 실호출을 한 사이클 10건 넘게. Codex와 직접 쓰기는 이 제한을 안 받는다

## 조심할 것

- **"없다"는 보고는 코드로 확인하기 전까지 전제로 쓰지 않는다**
- **문자열 유사도로 중복 규모를 판단하지 않는다.** 6.2배 틀린 적이 있다
- **검사기를 만들면 프롬프트에도 넣는다.** 안 그러면 아무도 안 부른다
- **표 비율은 지표가 아니다.** 2층 stack이 표로 옮겨가면 비율이 오히려 오른다. 지표는 오형 건수다
- **`block`을 남발하면 내용을 빼서 통과하는 답이 이긴다.** 지적 수가 줄기만 하면 재시도가 채택되기 때문이다
- **`rtk`가 파이프 출력을 자른다.** curl 결과는 파일로 받아서 읽는다
- React는 `#{n}`을 `#<!-- -->3`으로 낸다. 순진한 grep은 못 찾는다
- 할당량 키가 IP인데(`quota/key.ts`) 투표 키는 국내 캐리어 NAT 때문에 IP를 일부러 안 쓴다(`vote/identity.ts`). `QUOTA_ANON_DAILY`를 정상값으로 되돌리면 NAT 뒤 여러 명이 한 사람 몫을 나눈다

## 알람

사용자가 Remote Control을 켜뒀다. **사람이 정해야 하는 것이 생기면 알람을 보내되, 답을 기다리지 않고 계속 판다.** 스스로 정하고 근거를 남긴 뒤, 사용자가 뒤집을 수 있게 되돌리는 법을 적는다.
