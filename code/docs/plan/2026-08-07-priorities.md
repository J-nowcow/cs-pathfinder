## 순서

### 1. 검색에 열어준다 — 제일 값싸고 제일 크다

구글 색인 **0건**. `robots.txt`·`sitemap.xml` 둘 다 404다.

그런데 재료는 다 있다. `/q/…`는 완전 서버 렌더이고(JS 없이 curl로 본문이 다 온다), 질문마다 title·description이 다르고, `/questions` 한 장에 251개 링크가 걸려 있다. **파일 두 개가 없어서 251개가 통째로 묻혀 있다.**

- `app/sitemap.ts`·`app/robots.ts`. `/api/catalog`가 재료를 이미 내놓는다
- `/map` 노드에 `<a href>`가 **0개**라 크롤 경로가 끊긴다. 같이 본다
- 공개 페이지가 전부 `no-store`다. 홈 한 번에 RSC 프리페치 12건, `/questions`는 28건이 매번 오리진을 깨운다. 유입이 늘면 비용으로 돌아온다

홍보를 안 했으니 지금 유입 경로는 존재하지 않는다. 이걸 먼저 열지 않으면 나머지가 아무도 안 보는 곳에서 좋아진다.

### 2. 도식을 넓힌다 — 스타를 부르는 것은 이것이다

`2026-08-07-diagram-vocabulary.md`의 순서를 따른다.

- **0단계 완료** (2026-08-07 밤). stack의 뜻을 좁히고 검사기에 넣었다. 도피처가 표가 아니라 **stack**이었다 — `parseStack`이 절대 실패하지 않아 무엇이든 층으로 받는다. 표 127개 중 오형 24%인데 stack 56개 중 41%다
- **1단계 `:::state`** — 상태 전이. 고치는 질문 14건. TCP 상태 머신을 표로 그리고 있다
- **2단계 `:::tree`** — 무엇이 무엇에 속하는가
- **3단계 `:::memory`** — 어디에 놓이고 어느 쪽으로 자라는가
- **4단계 `:::timeline`** — 누가 같은 시간에 무엇을 하는가

만들지 않는 것: 막대그래프, 토폴로지. 근거는 설계 문서에 있다.

**지표를 조심한다.** 2층 stack 30개가 표로 옮겨가면 표 비율이 51%→63%로 **오른다.** 표 비율은 지표가 아니다. **"오형 71건"이 지표다.**

새 도식 하나를 끝낼 때마다 **프롬프트와 검사기에 같이 넣는다.** 안 그러면 렌더러만 있고 모델이 안 쓴다 — `prose.ts`가 그 꼴이었다(검사기가 있는데 아무도 안 불러서 생성분 23.7%가 번역투를 달고 통과).

### 3. 중복을 정리하고 빈 분야를 채운다

질문 251개 중 **119개(47.4%)가 중복에 얽혀 있고 잉여만 31개**다. 문자열 측정은 5쌍밖에 못 잡았다 — **6.2배 과소계상**이다.

- 지우기: 확실한 중복 31개. **운영 DB 쓰기라 승인이 필요하다.** 한쪽에 이미 판 경로가 붙어 있을 수 있어 어느 쪽을 남길지도 정해야 한다
- `인프라 · 보안` 19개 중 **9개가 다른 분야 CS 기초의 재등재**다(컨텍스트 스위칭·페이징·뮤텍스·트라이). 미분류 수용소가 됐다. 원 분야로 되돌리고 실제 보안 주제로 채운다
- 기준선 대비 **프레임워크 22개·언어 16개 부족**. 둘 다 참조 레포에서 1~2위다
- **구조적 공백**: 251개에 컨테이너·쿠버네티스·테스트·빌드·모니터링이 **단 한 건도 없다.** Raft/Paxos도 0건. 개별 누락이 아니라 분야가 통째로 빠졌다
- 시드는 412개 중 **339개(82%)**가 아직 쓸 만하다. 소재 고갈은 걱정거리가 아니다

새 질문은 Gemini만 쓸 이유가 없다. 직접 쓰거나 Codex에 맡기면 무료 한도와 무관하다.

### 4. 진단 도구가 거짓말을 하는 것을 고친다

`check:graph`는 `qedge`만 읽는데 지도는 `qedge + semantic_relation`을 합쳐 그린다. 그래서 **"고립 95%"라고 하지만 실제는 21%**다. 74%p 차이다.

이 판정으로 결정하면 있는 기능을 없다고 오판한다. 고친 뒤 볼 숫자는 고립률이 아니라 **파편화** — 271개가 91조각, 최대 덩어리 41개(15%). `votes>=2` 필터가 최대 덩어리를 23%→15%로 깎는데 이 필터가 값어치를 하는지가 다음 실험이다.

덧붙여 **`qnode.embedding`이 271개 전부 NULL이고 `qnode_equivalence`는 0행**이다. 의미 기반 중복 방지가 스키마에만 있고 한 번도 안 돌았다.

### 5. 돌아올 이유를 만든다

재방문 장치가 문자 그대로 **0개**다. manifest·ServiceWorker·RSS·이메일·알림 전부 없다.

그런데 `localStorage`에 판 기록이 남는다(596B). **홈에 보여줄 자리가 없을 뿐이다.** "어제 여기까지 팠어요 →" 한 줄은 서버 작업 없이 된다. 그다음이 manifest로 홈 화면 추가.

### 6. 회원가입 — 아침에 정한다

`2026-08-07-auth-design.md`가 5단계로 쪼갰다. ① 로그인만(구글) → ② 여정 서버 저장·병합 → ③ `/me` 공부기록 → ④ 복습·북마크 → ⑤ 카카오.

**결정이 필요한 것 셋**

1. Auth.js v5(beta) 의존을 질 것인가. Clerk는 카카오 미제공 + 사용자 저장소가 둘로 갈려 탈퇴가 두 시스템에 걸린다. Supabase Auth는 Neon과 구조적으로 불가
2. **개인정보처리방침이 로그인 버튼보다 먼저** 떠 있어야 한다(제30조). 버튼이 먼저 나가면 그 시점부터 위반이다
3. 익명 지원을 계속할 것인가. 접으면 README가 약속한 "가입 없이"를 깨는 회귀다

**2단계가 제일 위험하다.** OAuth는 전체 페이지 이동이라 `ReadingView`가 재마운트되고 `useState`가 또 1개짜리 여정을 만든다. **오늘 고친 그 버그와 정확히 같은 모양**이고 이번엔 그 1개짜리가 서버로도 올라간다.

**"남의 트리 추천"은 접었다.** `tree_vote` 1행·공유 트리 1개라 행렬이 1×1이다. 계정으로 안 풀리고 트래픽이 풀 문제다.

## 승인이 필요해 멈춰 있는 것

| | 왜 |
|---|---|
| 중복 31개 삭제 | 운영 DB 쓰기. 어느 쪽을 남길지도 정해야 한다 |
| 사용자가 판 노드 13개 정리 | 62자 경어체 질문이 제목·URL에 박혔다. 게이트는 이미 고쳤고 이건 그 전에 만들어진 것 |
| 익명 하루 한도 9999 | 실제로 얼마로 되돌릴지. 되돌리면 아래 잠복 버그가 드러난다 |
| 히어로 배경 시안 A/B/C | 폰에서 배경이 h1을 100% 덮는다 |

**잠복 버그** — 할당량 키가 **IP**인데(`quota/key.ts`), 투표 키는 국내 캐리어 NAT 때문에 IP를 일부러 안 쓴다(`vote/identity.ts`). 같은 논리가 할당량에도 적용된다. 지금은 한도가 9999라 안 드러나지만 **정상값으로 되돌리는 순간 NAT 뒤 여러 명이 한 사람 몫을 나눈다.**
