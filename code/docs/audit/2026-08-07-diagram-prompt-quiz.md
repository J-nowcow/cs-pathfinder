# 프롬프트가 새 도식을 고르게 하는가 — 12문항 시험

측정: 2026-08-07 06:30 · 대조: Codex (`read-only`, `high`)
· 재현: `src/lib/llm/generate.ts`의 도식 절만 떼어 주고 질문 12개에 울타리만 고르게 한다

## 왜 쟀는가

도식 어휘를 여섯으로 넓혔는데 **운영 코퍼스 276편에서 table이 49.6%, state 1개,
tree 1개, timeline 0개, memory 0개**다. 두 가지 설명이 가능했다.

1. 프롬프트가 불친절해서 모델이 새 형태를 못 고른다
2. 코퍼스가 어휘보다 **먼저** 만들어졌을 뿐이다

둘은 다음 할 일이 완전히 다르다. 1번이면 프롬프트를 고쳐야 하고, 2번이면
프롬프트는 그대로 두고 **다시 만들어야** 한다(운영 DB 쓰기 — 승인 필요).

Gemini는 05:00 이후 못 쓰지만 이 시험에는 필요 없다. 지침만 주고 무엇을 고르는지
보는 것이라 어느 모델이든 **지침의 명확도**를 잰다.

## 결과 — 프롬프트는 멀쩡하다

**12개 중 10개를 망설임 없이 맞혔다.** state·tree·memory·timeline을 각각 제자리에
골랐다. 코퍼스가 표에 몰린 것은 프롬프트 탓이 아니다.

| 질문 | 골라야 할 것 | 고른 것 |
|---|---|---|
| TCP 연결 종료 상태 | state | state |
| 두 스레드가 같은 잔액 | timeline | timeline |
| 프로세스 주소 공간 | memory | memory |
| B-tree 노드 | tree | tree |
| OSI 7계층 | stack | stack |
| 낙관적·비관적 락 | 표 | 표 |
| HTTPS 요청 순서 | flow | flow |
| 서킷 브레이커 | state | state |
| 자바 예외 클래스 | tree | tree |
| 블로킹 입출력 | timeline | timeline(망설임) |
| 스택 오버플로 | memory | stack(틀림) |
| 데드락 | timeline | 도식 없음(틀림) |

## 빈틈 셋을 고쳤다

### 1. 계층 예시에 "메모리 영역"이 있었다

`계층 (stack)`의 예시가 `프로토콜 계층, **메모리 영역**, 캐시 단계`였다.
`memory` 도식과 정면으로 겹친다. 스택 오버플로에서 stack을 고른 이유가 이것이다.

예시를 `프로토콜 계층, 캐시 단계, 추상화 층`으로 바꾸고 한 줄을 더했다 —
**주소 위에 놓인 것은 전부 memory**, stack은 주소와 무관하게 얹힌 것.

### 2. timeline과 state를 가르는 기준이 없었다

블로킹 입출력은 지침에서 timeline의 예시인데, 프로세스 상태는 state의 예시다.
둘 다 해당해 보인다. **주체를 세라**는 기준을 넣었다 — 하나면 state, 둘 이상이
같은 시간표 위에 있으면 timeline.

### 3. 데드락이 어디에도 안 걸렸다

`도식 없음`을 골랐다. 손으로 쓴 데드락 노드는 timeline을 쓰는데 지침이 그리로
안 이끈다. "여럿이 서로를 기다리며 멈춘 것도 timeline"이라고 못 박았다.

## 고친 뒤 다시 물었다

세 질문을 지침만 새로 읽혀 다시 물으니 **셋 다 망설임 없이** timeline · memory ·
timeline로 왔다. 남은 빈틈은 "없음"이었다.

## 그래서 다음은

프롬프트는 손볼 것이 없다. **표 편중은 코퍼스를 다시 만들어야 풀린다** —
`얕은계층` 34편이 특히 tree나 표로 옮겨야 할 것들이다. 운영 DB 쓰기라
사람이 정한다.
