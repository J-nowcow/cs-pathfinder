# 정확도를 재는 방식

해설 초안은 AI가 쓴다. 그래서 이 저장소는 정확도를 **짐작으로 말하지 않고
재서 기록한다.** 이 폴더가 그 기록이다 — 측정 방법, 나온 숫자, 그리고
**시도했다가 반증된 접근**까지.

## 핵심 숫자 (시계열)

| 날짜 | 무엇을 쟀나 | 결과 |
|---|---|---|
| 8/7 | 예비 표본 20편을 다른 모델(Codex)로 대조 | **15편에서 사실 오류** |
| 8/7 | 전수 276편 1차 훑기 | 하드 오류 80편 · 118건 → 전부 수정 |
| 8/8 | 이미 고친 40편을 같은 잣대로 재검 | **17편에 오류가 남아 있었다** — 한 번으로는 부족하다 |
| 8/9 | 모델이 쓴 245편 전부 4회차 재검 | **오류 59건 수정.** 회차별 오류율 7~43% |

숫자에서 배운 것 둘:

- **"말뭉치 오류율 X%"라는 한 숫자는 없다.** 배치마다 6배 갈린다
- **고친 사람이 다음 오류를 만든다.** 재검에서 잡힌 오류 중 셋은 앞선
  수정 작업이 만든 것이었다. 그래서 훑기는 한 번으로 끝나지 않는다

## 반증 기록 — 시도했고, 안 됐다

같은 실험을 두 번 하지 않으려고 남긴다. **여기 있는 방법을 다시 제안하기
전에 해당 문서부터.**

| 문서 | 반증된 것 |
|---|---|
| [`2026-08-08-table-share.md`](2026-08-08-table-share.md) | "표가 너무 많다 → 고치자"를 세 번 쟀고 세 번 다 고칠 결함이 아니었다 |
| [`2026-08-07-near-duplicate-questions.md`](2026-08-07-near-duplicate-questions.md) | 문자열 유사도로 중복 규모 판단 — **6.2배 과소계상.** 임계값으로 못 메운다 |
| [`2026-08-07-diagram-prompt-quiz.md`](2026-08-07-diagram-prompt-quiz.md) | 프롬프트가 새 도식 종류를 실제로 고르는지 12문항 시험 |

계획 문서(`../plan/2026-08-08-24h-autonomy.md`)에도 반증이 더 있다 —
단정 어휘 검사기(오탐 대부분), 규모별 매칭률 곡선(회차 간 7~17% 요동이라
지표로 못 씀).

## 작업 파일

`_` 접두 파일과 `slices/`·`fixes/`는 측정 중간 산출물이다(표본 원문·수정
전 본문 백업). 보고서가 아니라 재현용 재료라 정리하지 않고 그대로 둔다 —
지우면 "그때 정확히 무엇을 보고 판정했나"를 되짚을 수 없다.

## 방법의 뼈대

1. **다른 모델로 대조한다.** 쓴 모델이 스스로 검사하면 같은 사각지대를 공유한다
2. **고치기 전에 지금도 있는지 센다.** 낡은 지적을 고치겠다고 멀쩡한 본문을 건드리는 것을 막는다
3. **고친 뒤 같은 잣대로 다시 잰다.** 3번 문서가 이것이 필수임을 보였다
4. **검증 못 하는 지적은 반영하지 않는다.** 확인 불가한 주장은 완화된 문장으로만 쓴다
