# 같은 잣대로 다시 재 봤다 — 사실 오류율

2026-08-08. 외부 모델(Codex)에 **엄격 기준**으로 사실 검증을 맡겼다. 기준은 하나다 — **한 편에 사실과 다른 단정이 하나라도 있으면 `틀림`.**

## 숫자

| | 표본 | 틀림 | 부정확 | 맞음 | 사실 오류율 |
|---|---|---|---|---|---|
| 내가 손으로 쓴 것 | 11 | 7 | 2 | 2 | **64%** |
| 모델이 쓴 것 | 20 | 15 | 2 | 3 | **75%** |

모델 표본은 258편에서 **분야마다 둘씩** 떴다. 번호 순으로 일정 간격을 두고 골라 취향을 뺐다.

**공들여 손으로 쓴 것도 64%였다.** 이것이 이 측정의 핵심이다. 모델 탓만 할 수 없다.

## 앞선 측정과 왜 다른가

`2026-08-07-fact-check-full.md`는 "열 편 중 셋에 면접관이 되물을 서술"이라고 적었다. 29%다. 지금은 75%다.

**둘 다 맞다. 잣대가 다르다.** 그때는 "면접에서 감점될 만한 것"을 셌고, 지금은 "조건을 빼고 단정한 것"까지 전부 센다. 예를 들면 이런 것들이 이번에 걸렸다.

- `K-means는 구형 클러스터만 찾는다` — 등방성 군집에 유리한 것이지 "구형만"은 아니다
- `JWT는 만료까지 못 막는다` — 취소 목록이나 키 교체로 막을 수 있다. 서버 상태가 다시 생길 뿐이다
- `캐시와 TLB가 무효화된다` — 전환할 때 통째로 비우지 않는다. 밀려나는 것이다
- `DP는 항상 최적해를 보장한다` — 상태와 점화식이 문제를 맞게 담았을 때다
- `컴파일러가 논리적 오류를 잡는다` — 구문과 타입은 잡지만 논리는 못 잡는다

## 무엇을 고쳤나

이번 사이클에 **명백히 틀린 아홉 자리**를 고쳤다. 위 다섯 가지와 그에 딸린 표 칸이다.

나머지는 대부분 **조건을 덧붙여야 하는 것**이라 한 자리씩 손으로 봐야 한다. 258편을 이 잣대로 다 훑는 것은 남은 시간에 못 한다.

## 그래서 무엇을 할 것인가

**숨기지 않는다.** 대문과 해설 파일에 "AI가 썼고 틀릴 수 있다"는 말은 이미 있지만, 이제 **잰 숫자**가 있다.

세 가지를 나눠 본다.

1. **지금 당장** — 측정값을 공개한다. "20편을 엄격 기준으로 재니 15편에 조건이 빠져 있었다"
2. **다음** — 새로 쓰는 것부터 이 잣대로 검증하고 나간다. 이미 나간 258편은 조회수 많은 것부터
3. **구조적으로** — 어휘 검사기로는 못 잡는다(별도 측정으로 확인). 외부 모델 검증을 발행 앞에 넣는 것이 유일한 길이다
