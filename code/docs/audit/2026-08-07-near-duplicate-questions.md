# 거의 같은 질문이 따로 서 있다

2026-08-07 측정. 운영 `/api/roots?limit=400`으로 질문 **252개** 전부를 받아 쟀다.

> **정정 (같은 날, 의미 기준 전수 대조 뒤)**
>
> 아래 문자열 기준 측정은 **6.2배 과소계상이다.** 뜻으로 전수 대조하니
> **119개(47.4%)가 중복에 얽혀 있고 그중 잉여만 31개(12.4%)**였다.
> 정리하면 251 → 220(확실한 중복만) 또는 251 → 185(비슷한 것까지).
>
> 왜 놓쳤나 — 문자열 겹침은 **낱말이 겹칠 때만** 잡는다. 놓친 것 셋:
> ① 동의어·표기(`읽기`↔`조회`, `RDB`↔`SQL`)
> ② **분야를 넘는 쌍** — 확실한 중복 29군집 중 6군집이 다른 분야끼리다.
> 특히 `인프라 · 보안` 19개 중 **9개가 다른 분야 CS 기초의 재등재**다
> (컨텍스트 스위칭·페이징·뮤텍스·트라이). 미분류 수용소가 됐다
> ③ 하나의 지식을 원인/해결/기준으로 3분할한 것(해시 충돌 4개)
>
> **교훈: 문자열로는 중복의 표면만 본다.** 임계값을 어떻게 조절해도
> 6배 차이를 메울 수 없다. 아래 방법은 "확실히 같은 것"을 값싸게
> 잡는 데만 쓰고, 규모 판단에 쓰면 안 된다.
>
> 덧붙여 **`qnode.embedding`이 271개 전부 NULL이고 `qnode_equivalence`는
> 0행이다.** 의미 기반 중복 방지가 스키마에만 있고 한 번도 안 돌았다.

## 무엇을 쟀나

조사를 떼고 토큰으로 자른 뒤 자카드 겹침이 0.6을 넘는 쌍을 세었다. **9쌍**이 나왔고, 눈으로 보니 그중 **5쌍이 진짜 중복**이다.

| 겹침 | 두 질문 | 판정 |
|---|---|---|
| **1.00** | `HTTP 메서드 선택의 기준은 무엇인가?`<br>`HTTP 메서드 선택 기준은 무엇인가?` | 중복. **조사 `의` 하나 차이** |
| 0.75 | `가상 메모리 관리 시 페이징과 세그멘테이션은…`<br>`가상 메모리 관리에서 페이징과 세그먼테이션은…` | 중복. **철자(`세그멘`/`세그먼`)와 조사만** |
| 0.75 | `인덱스 생성 시 읽기 성능과 쓰기 성능의 트레이드오프는?`<br>`인덱스 생성 시 조회 성능과 쓰기 성능의 트레이드오프는?` | 중복. `읽기`/`조회`가 같은 뜻 |
| 0.71 | `사용자 모드에서 커널 모드로 진입하는 이유는?`<br>`사용자 모드와 커널 모드 전환의 이유는?` | 중복 |
| 0.67 | `컨텍스트 스위칭 비용은 구체적으로 어디서 발생하는가?`<br>`컨텍스트 스위칭은 왜 비용이 발생하는가?` | 사실상 같은 답 |

나머지 4쌍은 **오탐**이다. `~를 사용하는 이유는 무엇인가?`, `~ 선택 기준은 무엇인가?` 같은 **문형이 같아서** 걸린 것이고 내용은 다르다(`커넥션 풀` vs `트라이` vs `ORM`, `최단 경로 알고리즘` vs `GC 알고리즘`).

**진짜 중복은 252개 중 5쌍 ≈ 2%다.** 지금은 작지만 질문이 늘수록 같은 비율로 는다.

## 왜 생겼나

배치 게이트의 중복 판정이 **문자열 그대로 비교**다.

```
scripts/build-generated-nodes.ts:102
  const key = `${m.identityScope}::${m.question}`
  if (seen.has(key)) bad.push('중복')
```

`의` 하나, 띄어쓰기 하나, `세그멘`/`세그먼` 하나만 달라도 다른 키가 된다. 자카드 1.00짜리 쌍이 통과한 이유가 이것이다.

운영 경로의 매칭 게이트(`runGate`)는 후보를 LLM에게 보여주고 고르게 하므로 이런 것을 잡을 수 있는데, **배치는 그 게이트를 안 탄다.** 코퍼스를 만들 때 한 번에 만들어져서 서로를 후보로 못 봤다.

## 무엇을 해야 하나

1. **배치 중복 키를 정규화한다.** 공백 제거 + 조사 제거 + 소문자화 정도면 위 5쌍 중 최소 2쌍(자카드 1.00, 0.75 철자)이 잡힌다. `content-rules.ts` 옆에 순수 함수로 두고 시험을 건다
2. **뜻이 같은 낱말 쌍**(`읽기`/`조회`, `진입`/`전환`)은 문자열로 못 잡는다. 이건 `semantic_relation` 판정이나 사람 눈이 할 일이다. 새 규칙을 억지로 만들지 마라 — 기준선을 걸 위험이 크다
3. **이미 DB에 있는 5쌍**은 지우거나 합쳐야 하는데 **운영 DB 쓰기라 승인이 필요하다.** 여기 적어만 둔다. 합칠 때는 어느 쪽을 남길지도 정해야 한다 — 한쪽에 이미 판 경로가 붙어 있을 수 있다

## 재현

```bash
curl -s "https://cs-pathfinder.vercel.app/api/roots?limit=400" > /tmp/r.json
# 조사 제거 후 자카드 0.6 이상 쌍을 센다
```

## 한계

- 자카드는 **문형이 같으면 오탐**한다(9쌍 중 4쌍). 임계값을 올리면 진짜 중복도 놓친다
- 루트 질문만 봤다. 사용자가 판 `on_demand` 노드는 이 목록에 없다
- 뜻은 같은데 낱말이 전혀 다른 쌍은 이 방법으로 못 찾는다
