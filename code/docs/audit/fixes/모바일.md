## 031700b2-742f-49a5-a571-e64f7034fda4

질문: 안드로이드에서 메모리 누수가 발생하는 주원인은 무엇인가?
판정: 고침
지적: 누수가 유지되는 참조의 도달 방향이 반대로 그려져 있다

근거: GC가 회수하지 못하는 이유는 GC Root에서 Activity로 도달할 수 있기 때문이다. 화살표는 Root에서 Activity를 향해야 한다. 같은 해설의 본문도 "내부 클래스가 살아있으면 Activity도 메모리에 남는다"로 그 방향을 말하고 있어 표만 거꾸로다. 같은 파일의 다른 편("화면이 닫혔는데 객체가 남는 이유는?")은 GC Root → 싱글턴·콜백 → Activity·View로 올바르게 그렸다.

원래: | 참조 체인 | Activity $\rightarrow$ 익명 클래스 $\rightarrow$ 외부 객체 |
고침: | 참조 체인 | GC Root·장수 객체 $\rightarrow$ 익명 클래스·콜백 $\rightarrow$ Activity |

## c6f28d19-8a07-4f36-9659-ca576ec2685d

질문: 백그라운드 제약을 피하는 방법은 무엇인가?
판정: 고침
지적: 포그라운드 서비스도 종료될 수 있고 WorkManager는 프로세스 종료를 막는 수단이 아니다

근거: 두 수단의 목적을 "강제 종료 방지"로 묶은 것이 틀렸다. WorkManager는 프로세스가 죽는 것을 막지 않고 죽은 뒤 다시 예약한다. 같은 파일의 다른 편("앱이 백그라운드에서 죽는 이유는?")이 "프로세스가 죽어도 시스템이 나중에 다시 실행하게 한다"로 정확히 쓰고 있어 서로 어긋난다.

원래: 앱이 보이지 않아도 시스템이 강제 종료시키지 않도록 알림을 띄우거나 예약 작업을 등록하는 방식이다.
고침: 앱이 보이지 않아도 일을 끝내도록, 사용자가 인지해야 하는 작업은 알림을 띄우고 지연 가능한 작업은 예약해 두는 방식이다.

## ad1c8aaa-dd18-43ec-96c6-1bc2ffae28b6

질문: 푸시 알림이 안 오는 이유는 대개 무엇인가?
판정: 고침
지적: FCM은 이를 '할당량 차감'으로 설명하지 않는다. 남용은 우선순위 강등이나 알림 위임 대상이다

근거: 지적의 근거는 절반만 맞다. **할당량이라는 개념 자체는 실재한다** — 안드로이드 앱 대기 버킷(App Standby Buckets)은 버킷별로 높은 우선순위 FCM 메시지 할당량을 둔다. 다만 그 할당량을 정하는 것은 '남용'이 아니라 앱 사용 빈도이고, 사용자에게 보이는 알림으로 이어지지 않는 높은 우선순위 남용의 결과는 우선순위 강등이다. 원문은 이 둘을 하나로 뭉쳐 인과를 잘못 이었다. 고침 문장에 두 기제를 나눠 담는다.

원래: 그러면 절전을 뚫고 즉시 전달되지만 무제한은 아니다 — 남용하면 할당량이 깎여 오히려 더 늦어진다.
고침: 그러면 절전을 뚫고 즉시 전달되지만 무제한은 아니다 — 앱 대기 버킷별로 높은 우선순위 메시지 할당량이 있다. 알림으로 이어지지 않는 남용은 우선순위 강등을 부른다.
