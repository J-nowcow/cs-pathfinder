## e2a3399c-208b-4918-a710-97027c0f9bc7

질문: 데몬 프로세스는 왜 세션 리더로 지정되지 않는가?
판정: 고침 (지적 3건 전부 수용)
지적: 이중 fork의 목적·SIGHUP 전달 규칙·`setsid()` 효과가 모두 사실과 어긋난다
비고: 이 편은 `cs/explanations/운영체제.md`에 실려 있지 않다. 원문은 `slices/slice-01.md` #16이며 문자열이 일부 깨져 있다(`mãos a own sessiony`, `분리//분리된다`, 중복 어절). 깨진 부분은 고침 문장에 함께 정리했다.

원래: 백그라운드에서 계속 실행되어야 하므로 제어 터미널로 인한 종료 신호를 받지 않기 위해서다.
고침: 세션 리더만 제어 터미널을 획득할 수 있어서다. 리더가 아니면 터미널을 다시 붙잡을 일이 없어 터미널이 끊겨도 신호를 받지 않는다.

원래: 사용자가 로그아웃하면 세션 리더가 받은 SIGHUP 신호를 모든 프로세스에만 보낸다. 데몬은 의도적으로 세션 리더가 mãos a own sessiony는 잊고 새 세션을 만들어 리더가 아닌 자식으로 남는다.
고침: 터미널이 끊기면 SIGHUP은 세션 리더에게 간다. 로그아웃할 때 셸이 자기 작업들에 SIGHUP을 보내기도 한다. 데몬은 새 세션을 만든 뒤 다시 fork해 리더가 아닌 자식으로 남는다.

원래: setsid() 시스템 호출을 setsid() 시스템 호출을 통해 세션과 프로세스 그룹으로적으로지정되지 않은 상태로 분리//분리된다. 이를 통해 터미널과의 연결 고리를 게 끊어내어 시스템 리더가 종료 신호를를 보낸다고 해도 영향을 받지지 않고 계속 실행된다.
고침: 첫 자식이 `setsid()`를 부르면 새 세션의 리더이자 새 프로세스 그룹의 리더가 되면서 제어 터미널이 떨어진다. 여기서 한 번 더 fork하면 최종 데몬은 리더가 아니라 터미널을 다시 획득할 수 없다.

## ebde4f31-83c4-4078-9812-1262400b24ce

질문: 동기/비동기 및 블로킹/논블로킹의 차이는 무엇인가?
판정: 고침 (지적 2건 중 1건 반려)
지적: (A) 동기·비동기를 "완료 여부를 누가 확인하느냐"로 정의한 것은 표준 기준이 아니다 (B) 논블로킹이 폴링을 요구한다고 쓰고, 폴링을 비동기 구현체라 했다
반려 사유: (A)는 반려한다. "완료를 누가 챙기느냐"는 국내 면접 대비 자료에서 가장 널리 통용되는 구분 방식이고, 지적이 제안한 "완료와 후속 실행이 결합되는 방식"과 사실상 같은 내용을 다르게 표현한 것이다. Future 폴링 같은 경계 사례로 무너지는 단순화이긴 하나 면접에서 틀렸다고 할 수준은 아니다.

원래: 제어권을 바로로 돌려받는 논블로킹 방식은 호출한 쪽에서 계속해서 작업 완료 여부를 확인해야 한다. 이를 폴링(Polling)이라고 하며, 비동기 방식의 구현체로 많이 쓰인다.
고침: 제어권을 바로 돌려받는 논블로킹 방식은 호출한 쪽이 완료 여부를 다시 확인해야 한다. 반복해서 확인하는 것이 폴링이고, `select`·`epoll` 같은 준비 상태 통지로 대신할 수도 있다.

원래: | 간접 비용 | 캐시와 TLB가 무효화되어 다시 채워야 한다 | **이쪽이 본체** |

## 3ddad76b-7308-4416-8d74-bbb8947b8e43

질문: 동기화 문제를 하드웨어적으로 어떻게 해결하는가?
판정: 고침 (지적 3건 전부 수용)
지적: (A) 원자적 명령의 보장 범위를 "다른 프로세스가 개입 못 함"·"컨텍스트 스위칭이 없음"으로 잘못 설명했다 (B) CAS의 조건이 반대로 서술됐다 (C) 인터럽트 비활성화가 실무에서 안 쓰인다고 단정했다

원래: 원자적 명령어로 처리한다. CPU가 명령어를 실행하는 동안 다른 프로세스가 개입하지 못하게 막아 메모리 접근을 보장하는 방식이다.
고침: 원자적 명령어로 처리한다. 읽고 고쳐 쓰는 과정을 쪼갤 수 없는 한 단위로 만들어 다른 코어에도 중간 상태가 보이지 않게 보장하는 방식이다.

원래: Test-and-Set은 메모리 값의 현재 상태를 읽고 새로운 값을 쓰는 작업을 한 번에 처리한다. 중간에 컨텍스트 스위칭이 발생하지 않아 데이터 정합성을 지킨다.
고침: Test-and-Set은 메모리 값의 현재 상태를 읽고 새로운 값을 쓰는 작업을 한 번에 처리한다. 다른 코어의 접근이 그 사이에 끼어들 수 없어 정합성이 지켜진다.

원래: CAS는 기대하는 값과 현재 메모리 값의 일치 여부를를 확인하고 다를 경우에만 값을 바꾼다.
고침: CAS는 기대하는 값과 현재 메모리 값을 비교해 같을 때만 새 값으로 바꾸고 성공을 알린다.

원래: 인터럽트 비활성화는 간단하지만 멀티코어 환경에서는 모든 CPU의 인터럽트를 동시에 끄는 비용이 너무 커서 실무적으로 쓰이지 않는다.
고침: 인터럽트 비활성화는 간단하지만 자기 코어에만 통한다. 커널은 지금도 로컬 인터럽트를 끄되 다른 코어를 막으려면 스핀락을 함께 쓴다.

## 2ecb28ba-31f6-43b5-9473-afb9c0a3ccb5

질문: 컨텍스트 스위칭 시 CPU는 무엇을 저장하고 복원하는가?

고침: 주소 공간이 바뀌면 TLB를 비워야 할 수 있고 캐시에는 새 작업 집합이 들어와 미스가 늘어난다. 단순한 레지스터 복원보다 이 간접 비용이 더 크다.

## dd899ffd-3cf6-4877-9508-eb6e7238bae4
