# 사실 확인 — 게시된 해설 전수 대조

측정: 2026-08-07 04:30~07:05 · 대조: Codex (`model_reasoning_effort: high`, read-only)
· 도구: `slice-corpus.ts` → 병렬 에이전트 5 → `tally-factcheck.ts`

## 숫자를 어떻게 읽어야 하는가

**"깨끗 38%"를 그대로 쓰면 안 된다.** 그렇게 말하면 62%가 틀렸다는 뜻으로
읽히는데 사실이 아니다. 지적의 절반 이상이 `과일반화`이고 그중 상당수는
면접 대비 자료에서 잘못이라 하기 어렵다.

실제로 나온 것들이다.

> "조회를 위해 GET을, 생성은 POST, 수정은 PUT이나 PATCH를, 삭제는 DELETE를
> 사용한다."
> — POST는 생성 외 처리에도 쓰이고 PUT도 지정 URI를 생성할 수 있다

> "RDB는 수직 확장(Scale-up), NoSQL은 수평 확장(Scale-out)"
> — RDB도 샤딩과 분산 SQL로 수평 확장한다

둘 다 맞는 지적이다. 그런데 저 지적을 다 반영하면 글이 "제품과 설정별로
확인한다"로 끝나는 하나 마나 한 문서가 된다. 면접에서 저렇게 답하면 오히려
못 외운 사람으로 보인다.

그래서 **두 숫자를 따로 낸다.**

| | 뜻 |
|---|---|
| **하드 오류** (틀린 서술 + 용어 오용) | 면접관이 되물으면 그 자리에서 드러난다. 반드시 고친다 |
| 과일반화·부정확 | 더 정확할 수 있다는 지적. 판단해서 반영한다 |

## 결과

**276편 전수 대조에서 하드 오류가 있는 편이 80편(29.0%)이다.**

| | 편수 | 비율 |
|---|---|---|
| 하드 오류 있음 | 80 | 29.0% |
| 아무 지적 없음 | 106 | 38.4% |
| 과일반화·부정확만 | 90 | 32.6% |

지적 건수로는 이렇다.

| 종류 | 건수 |
|---|---|
| 틀린 서술 | 72 |
| 용어 오용 | 46 |
| 과일반화 | 185 |
| 부정확 | 94 |

비율이 묶음을 더해도 흔들리지 않았다 — 195편 29.2%, 223편 28.7%, 251편 29.5%,
276편 29.0%. 묶음별 하드 오류도 6~11편으로 고르다.

### 분모를 대조 모델에게 묻지 않는다

처음 합계가 **278편**으로 나왔다. 코퍼스는 276이다. 한 묶음이 자기가 본 편수를
28이 아니라 30으로 적었고(별표까지 붙여서) 그것을 그대로 더한 결과다.

판정은 대조 모델이 하지만 **몇 편이었는지는 우리가 안다.** 분모를 원본 묶음에서
직접 세도록 고쳤고, 어긋나면 경고를 찍는다. 지금은 한 묶음에서 경고가 뜬다.

`npx tsx scripts/tally-factcheck.ts`로 다시 셀 수 있다.

### 이 숫자가 뜻하는 것

**세 편 중 하나꼴로 면접에서 무너질 서술이 있다.** 이것이 이 서비스의 가장
큰 약점이고, 형태 검사기로는 원리적으로 못 잡는다.

앞서 표본 20편에서 나온 8/20(40% 깨끗)과 거의 같다. 표본이 대표성이 있었다 —
다음부터는 전수를 돌리기 전에 20편으로 먼저 재도 된다.

## 어떤 종류로 틀리는가

한 종류로 모인다 — **교과서에 그대로 실려 있는데 현실이 바뀐 자리**다.
모델이 학습한 대로 쓰면 틀린다.

1. **TLS 키 교환.** "비대칭키로 대칭키를 전달한다", "프리마스터 시크릿을
   보낸다". TLS 1.3은 그 방식을 제거했고 1.2도 현실에서는 (EC)DHE다.
2. **TLS 인증 방향.** "서로의 신원을 확인한다". 보통 서버만 인증한다.
3. **교착의 예방과 회피.** 회피를 "조건을 아예 만들지 않는 것"으로 설명.
   그것은 예방이다.
4. **다익스트라의 조건.** "양수"가 아니라 0을 포함한 비음수다.
5. **컨텍스트 스위칭.** "캐시와 TLB를 비운다". 캐시는 무효화되지 않고 TLB도
   PCID·ASID를 쓰면 통째로 안 비운다.

이 다섯은 **검사기 규칙으로 만들었다**(`src/lib/llm/stale-facts.ts`). 코퍼스
276편에서 7편이 걸리고 오탐은 0이다. 손으로 쓴 30편 기준선도 0이다.

걸린 7편은 **전부 Codex가 독립적으로 지적한 편과 일치한다.** 정규식과 대조
모델이 서로 다른 방법으로 같은 것을 짚었다.

## 방법과 그 한계

- 분류가 섞이게 라운드로빈으로 잘랐다. 분류순으로 자르면 한 묶음이 통째로
  데이터베이스가 되고 맡은 쪽이 "이 분야는 원래 이렇게 쓴다"는 기준을 스스로
  만든다.
- 묶음을 27~28편으로 잡았다. 더 크게 자르면 뒤쪽을 성기게 본다.
- **대조도 모델이 한다.** Codex도 틀릴 수 있다. 표본 20편에서 인용 일곱 개를
  원문과 대조해 지어낸 것이 없음은 확인했지만, **판정 자체가 맞는지는 전수로
  검증하지 않았다.** 특히 과일반화는 판정 기준이 사람마다 다르다.
- 하드 오류 80편도 **하나씩 사람이 보고 나서** 고쳐야 한다. 숫자는 어디를
  먼저 볼지 정하는 데 쓴다.

## 덤으로 드러난 것 — 깨진 글자

지적을 읽다 보니 사실 오류와 다른 종류가 섞여 나왔다. **본문의 글자 자체가
깨진 것**이다.

> "프로세스 그룹**으로적으로지정**되지 않은 상태로 분리"
> "제어권을 **바로로** 돌려받는 논블로킹 방식"
> "데이터가 **오기집단**될 수 있다"
> "락-프리 알고리즘을 **Senatorial Atomic** 연산을 이용해"

검사기의 `낱말반복`은 `락 락`처럼 **띄어 쓴** 반복만 본다. 붙어서 깨진 것은
못 잡는다. 사실 확인과 달리 이건 기계로 셀 수 있는 종류라 규칙으로 만들 만하다.
얼마나 있는지는 아직 안 셌다.
