### 데몬 프로세스는 왜 세션 리더로 지정되지 않는가?

`e2a3399c-208b-4918-a710-97027c0f9bc7` · slice-01 #16

  - **[틀린 서술]** “백그라운드에서 계속 실행되어야 하므로 제어 터미널로 인한 종료 신호를 받지 않기 위해서다.”
    왜: 전통적인 이중 fork에서 최종 프로세스를 세션 리더가 아니게 만드는 직접적인 목적은 제어 터미널을 다시 획득하지 못하게 하는 것이다.
    고침: `setsid()`로 기존 터미널에서 분리하고 다시 fork해 최종 데몬이 제어 터미널을 획득하지 못하게 한다.
  - **[틀린 서술]** “사용자가 로그아웃하면 세션 리더가 받은 SIGHUP 신호를 모든 프로세스에만 보낸다.”
    왜: 세션 리더가 SIGHUP을 받은 뒤 모든 프로세스에 전달하는 일반 규칙은 없다. 터미널 드라이버나 셸이 전경 프로세스 그룹 또는 작업에 신호를 보낸다.
    고침: 로그아웃과 터미널 단절 시 SIGHUP 전달 대상은 터미널과 셸의 작업 제어 동작에 따라 결정된다.
  - **[틀린 서술]** “setsid() 시스템 호출을 통해 세션과 프로세스 그룹으로적으로지정되지 않은 상태로 분리”
    왜: `setsid()` 호출에 성공한 프로세스는 새 세션의 세션 리더이자 새 프로세스 그룹의 리더가 된다.
    고침: 첫 번째 자식이 `setsid()`로 세션 리더가 된 후 다시 fork하면 최종 자식은 세션 리더가 아니게 된다.

### 동기/비동기 및 블로킹/논블로킹의 차이는 무엇인가?

`ebde4f31-83c4-4078-9812-1262400b24ce` · slice-02 #16

  - **[용어 오용]** "동기와 비동기는 호출한 함수의 완료 여부를 누가 확인하느냐의 차이이고"
    왜: 완료 여부를 누가 확인하는지는 표준적인 구분 기준이 아니다. 비동기 작업도 호출자가 상태를 확인할 수 있다.
    고침: 동기·비동기는 완료와 후속 실행이 결합되는 방식 및 완료 통지 방식의 차이라고 설명한다.
  - **[틀린 서술]** "제어권을 바로로 돌려받는 논블로킹 방식은 호출한 쪽에서 계속해서 작업 완료 여부를 확인해야 한다. 이를 폴링(Polling)이라고 하며, 비동기 방식의 구현체로 많이 쓰인다."
    왜: 논블로킹 호출이 지속적인 폴링을 요구하지는 않는다. `select`, `epoll`, `kqueue` 같은 준비 상태 통지를 사용할 수 있다.
    고침: 논블로킹 호출은 즉시 반환하며 이후 폴링이나 준비 상태·완료 통지를 사용할 수 있다고 쓴다.

### 동기화 문제를 하드웨어적으로 어떻게 해결하는가?

    고침: CAS는 현재 값과 기대값이 일치하면 새 값을 기록하고 성공을 반환한다.

    고침: 인터럽트 비활성화는 로컬 CPU 동기화에 사용되며 멀티코어 공유 데이터에는 스핀락 등이 추가로 필요하다.
