# 상태 전이 도식 시안

시안 `src/components/diagram/proto/StateProto.tsx` · 화면 `/zz-proto/state`

## 형태 — 상태마다 한 줄, 그 아래 나가는 길

세로는 나온 순서, 가로는 한 단뿐이다. 임의 그래프로 그리면 노드를 2차원에 흩뿌리고 선을 이어야 하는데, 앞선 SVG 시안(`DiagramSvg.tsx`)이 거기서 무너졌다 — 한 상태에서 두 갈래가 나가자 곡선과 이름표가 포개졌고, `bulge`·`labelY` 같은 손보정을 쌓다가 반려됐다. 배치를 없애면 그 실패가 통째로 사라진다.

## 배치 계산 없이 관계를 보인 방법

- **되돌아감** — 도착 칩에 `↑`(앞에 나온 상태) `↓`(아래) `↺`(제자리). 세로 순서가 고정이라 좌표가 아니라 두 색인의 비교다
- **합류** — 상태 머리에 `← 생성 · 실행 · 대기에서 온다`. 나가는 길만 그리면 `준비`로 셋이 모인다는 사실이 어디에도 안 남는다
- **끝** — 나가는 길이 없는 상태에도 줄을 준다. 지금은 `종료`·`TERMINATED`가 도착점으로만 스쳐 간다
- **갈림** — 한 머리 아래 여러 가지. 번호가 없으니 "그다음"이 아니라 "둘 중 하나"로 읽힌다

선은 전부 CSS다. `└`는 `border-l`+`border-b` 두 조각, 화살촉은 테두리 삼각형이라 SVG도 좌표도 없다. 폭 390·350·320 어디서도 `figure`가 가로로 밀리지 않는다(넘치는 것은 `sr-only` 43개뿐, 전부 1px로 잘려 있다).

## 파서 문법 제안 — 안 바꾼다

지금 `state`가 받는 `A -> B: 설명` 그대로 쓰되 설명 앞머리의 `[…]`를 가드로 본다. `실행 -> 대기: [입출력을 요청한다] CPU를 놓고 장치를 기다린다`. 시안은 렌더러에서 뗀다. 파서로 옮긴다면 `FlowStep`에 `guard?: string`을 더하고 `parseState`에서만 뽑되 `flow`는 그대로 둔다. 대괄호가 없으면 통째로 설명이 되므로 모델이 안 써도 잃는 것이 없다.
