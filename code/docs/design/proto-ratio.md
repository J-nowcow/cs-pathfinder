# 비교·비율 시안

`src/components/diagram/proto/RatioProto.tsx` · 시안 페이지 `/zz-proto/ratio`

## 왜 이 형태인가

자릿수가 벌어지는 값이 이 도식의 존재 이유다. 캐시 1 ns와 디스크 10 ms를 길이에 그대로 비례시키면 캐시는 0.00001칸이라 화면에서 사라진다. 그렇다고 막대 길이를 로그로 눕히는 것도 정직하지 않다 — 사람은 막대를 길이의 비로 읽는데, 로그 막대에서 두 배 긴 막대는 100배거나 1만 배거나 제멋대로다.

그래서 **길이를 재는 대신 칸을 센다.** 눈금을 자릿수 칸으로 끊고 한 칸이 10배라고 그림 위에 적었다. 칸 사이에 실선이 보이므로 읽는 동작이 "길이 어림잡기"에서 "칸 세기"로 바뀐다. 가장 작은 값도 한 칸을 받으므로 사라지지 않는다. 자릿수가 두 개 미만이면 이 장치를 끄고 길이에 그대로 비례시킨다(`scale='auto'`) — 안 벌어진 값에 로그를 씌우면 없는 왜곡을 만든다. 구성비는 따로 `RatioBand`다. 따로 있는 값을 견주는 것과 하나를 나눈 몫은 다른 이야기다.

## 무엇을 포기했는가

- **눈금의 정밀도.** 칸 눈금은 "몇 배쯤"까지만 읽힌다. 정확한 배수는 항목마다 글자로 적어 메운다.
- **단위 눈금(1ns·10ns·100ns).** 칸마다 `기준·×100·×1만`처럼 배수만 적는다. 단위를 모르는 채로도 그려야 하고, 390px에서 단위 눈금은 이름표가 서로 붙는다. 칸이 여섯을 넘으면 한 칸씩 건너뛰어 적는다.
- **띠 조각의 색 구분.** 쓸 수 있는 색이 강조색 한 벌뿐이라(`--d1`~`--d5`는 깊이 예약) 명도만 다른 청록 다섯이 된다. 조각은 번호로 가르고 아래 목록에 같은 번호를 단다. 8% 아래 조각은 번호가 안 들어가 자리로만 읽힌다.
- **작은 조각의 최소 폭.** 6바이트가 9%면 9%로 그린다. 최소 폭을 주면 "작다"는 사실 자체가 지워지는데 그 사실이 대개 요점이다.

## 파서 문법 제안

`stack`의 `이름 | 설명`을 잇는다. 둘째 칸이 **숫자**여야 하는 것이 이 문법의 자물쇠다 — `memory`가 `위로/아래로`로 stack과 갈리는 것과 같은 장치이고, 없으면 stack처럼 아무거나 받는 도피처가 된다.

```
:::ratio                      셋째·넷째 칸은 없어도 된다
L1 캐시 | 1 | 1 ns | 코어 안에 붙어 있다
NVMe SSD | 100000 | 100 µs
:::

:::band                       같은 문법. 합을 100으로 놓는다
이더넷 헤더 | 14
데이터 | 6 | | 실제로 나르는 것
:::
```

`이름 | 값 | 표시 | 보탬말`. 값은 항목끼리 같은 단위여야 하고 그림은 이 값으로만 그린다. 표시가 있으면 화면 글자는 그쪽이 이긴다(100000 ns를 `100 µs`로 적으려면 이것이 필요하다). 둘째 칸이 숫자가 아니거나 항목이 둘 미만이면 `null`을 돌려 문단으로 떨어뜨린다. `:::ratio 길이`로 칸 눈금을 끌 수 있게 두면 좋겠다.

## 확인한 것

폰 390px에서 가로 넘침 없음(`panelScrollW=390`), 이름이 두 줄로 접히는 행 없음, 자릿수 7단(칸 8개)에서 눈금 이름표가 안 겹침. 밝은·어두운 모드 양쪽. 폭이 절반(≈212px)으로 눌려도 이름만 두 줄이 되고 깨지지 않는다.
