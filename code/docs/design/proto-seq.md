# 주고받음 도식 시안

`src/components/diagram/proto/SeqProto.tsx` · 확인: `/zz-proto/seq`

## 왜 생명선인가

핸드셰이크는 **누가 공을 쥐고 있는지**가 내용이다. 지금 `flow`는 걸음마다
`클라 → 서버`를 글로 다시 읽혀서, 왕복이 잦을수록 그게 흐려진다. 기둥을 세우면
방향이 자리로 보인다. 시간이 아래로 흐르는 것은 걸음이 세로로 쌓여서 읽힌다.

반려된 SVG 시안의 문제는 SVG가 아니라 좌표였다. 이름표가 포개져서 `labelY`
보정을 손으로 쌓았고, 그런 보정은 다음 입력에서 또 깨진다. 그래서 좌표를 한 줄도
계산하지 않는다.

## 390px에서 셋 이상

**칸 안에 글자를 넣지 않는다.** 390px을 넷으로 나누면 97px이라 한글 설명이 안
들어간다. 칸이 나르는 것은 화살표와 기둥뿐이고, 설명은 아래 줄에서 폭을 통째로
쓴다. 주체가 늘어도 글자 칸은 줄지 않고 화살표만 짧아진다.

두 층이 같은 폭을 다르게 나눈다. 생명선은 `repeat(N, 1fr)`, 화살표는
`0.5fr repeat(N-1, 1fr) 0.5fr`. 양 끝이 반 칸이면 화살표 층의 격자선이 기둥
한가운데에 정확히 떨어져서 **주체 i의 기둥 = 격자선 i+2** 하나로 끝난다. 나눗셈은
브라우저가 한다. 설명 줄은 `bg-raised`라 뒤의 생명선을 덮어 선이 글자를 가로지르지
않는다. 넷이 한계다 — 다섯이면 기둥 이름부터 무너지므로 파서가 막아야 한다.

## 파서 문법

`flow`와 같은 줄 모양이라 모델이 새로 배울 것이 없다.

```
:::seq
클라이언트 -> 결제 서버: 승인 요청. 멱등 키 k를 같이 보낸다
결제 서버 -x 클라이언트: 응답이 끊긴다          ← 닿지 못한 걸음
2초 기다린다. 다음엔 4초 — 지수 백오프          ← 화살표가 없으면 노트
클라이언트 -> 클라이언트: 키 k를 들고 있는다     ← 이름이 같으면 자기 자신
클라이언트 -> 결제 서버: 같은 키 k로 다시 요청한다
:::
```

`->`·`→`·`=>`는 `FLOW_LINE`이 이미 받는다. 더한 것은 `-x` 하나뿐이다.
**재시도는 문법이 아니라 구조에서 나온다** — 같은 방향을 앞에서 이미 보냈고 그
사이에 실패가 있었으면 다시 보내는 것으로 그린다. `StateDiagram`이 되돌아가는 길을
알아내는 방식과 같다. 가드는 주체 4개, 걸음 8개, 기둥에 없는 이름이면 그 걸음은
설명만 남긴다.
