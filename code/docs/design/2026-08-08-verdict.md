# 도식 시안 다섯 — 판정

2026-08-08. 시안 다섯을 겨뤄 무엇을 본선에 올릴지 정한다. 판정자는 메인 세션, 평가자는 Codex(외부 모델, read-only)와 논증자 둘이다. **결론은 양쪽 논증 어느 쪽도 아니다** — 측정이 제3의 답을 가리켰다.

## 정정 (같은 날, 논증 둘이 들어온 뒤)

**아래 결론 중 `ratio` 채택은 철회한다.** 논증자 둘이 각각 원문을 짚었고 내가 대조해 확인했다.

`docs/plan/2026-08-07-diagram-vocabulary.md:170,191`이 코퍼스 249개를 **손으로 전수 분류**해 수치 막대를 이미 닫았다.

> **막대그래프 — A등급 0건.** 코퍼스에 수치 비교는 많지만 전부 두 값의 대소이지 여러 값의 분포가 아니다. `O(1)`과 `O(n)`은 길이로 그릴 수 있는 양이 아니다.

논증자가 따로 센 값도 같은 쪽이다 — 표본 219편 중 실측 단위(초·ms)를 말하는 것이 **6건(2.7%)**, RatioProto의 대표 예시(ns 대 ms 자릿수)에 해당하는 것은 **0건**이다.

**"표 136편이 표적"이라는 내 전제도 틀렸다.** 같은 문서 `:608`이 표 127개 중 **65~76%가 정당한 비교표**라고 못박았다. 도피처는 표가 아니라 **stack**이다 — 56개 중 A+B 오형 **88%**.

그리고 논증자가 진짜 병목을 찾았다. **`state`·`tree`·`memory`·`timeline`은 파서도 렌더러도 이미 배포돼 있는데 콘텐츠가 안 옮겨갔다.** 어휘 문서가 A등급 71건을 지목했는데 실사용은 state 1 · tree 1 · memory 0 · timeline 0이다. **새 어휘를 여는 것이 아니라 이미 연 어휘로 옮기는 것이 먼저다.**

## 왜 이렇게 갈렸나

### `flow`는 이미 "행위자 사이의 순서"다

`blocks.ts:18`이 `flow`를 이렇게 정의한다.

> 행위자 사이의 순서. 3-way handshake 같은 것

생성 프롬프트도 3-way handshake를 대표 예시로 쓴다(`generate.ts:60`). **seq 시안이 그리려는 것과 같은 것이다.** 그래서 `:::seq`를 새로 여는 것은 같은 뜻의 문법을 둘 만드는 일이고, 모델이 둘 중 하나를 잘못 고를 자리를 새로 만든다.

### 그런데 저장된 `flow` 73개는 한 모양이 아니다

`npm run measure:flow-shape`로 전수를 셌다.

| 모양 | 개수 | 맞는 그림 |
|---|---|---|
| 왕복 — `A→B`와 `B→A`가 둘 다 있다 | 31 (42.5%) | 기둥과 화살표 (seq) |
| 선형 사슬 — `A→B→C`, 안 돌아온다 | 22 (30.1%) | 세로 트렁크 (flow 시안) |
| 그 밖 — 갈라지거나 섞였다 | 20 (27.4%) | — |

마디 수는 2~7개, **5개를 넘는 것은 5개(6.8%)**뿐이다.

**어느 한 렌더러로 통째로 갈아끼우면 절반이 망가진다.** 왕복을 트렁크로 그리면 오간 것이 사라지고, 선형을 기둥으로 그리면 단계마다 기둥이 하나씩 서서 읽을 수 없다.

### 그래서 모양을 보고 고른다

파싱된 `steps`만 보면 어느 모양인지 알 수 있다. 문법을 새로 열 필요도, 저장된 본문을 다시 만들 필요도 없다.

- `A→B`와 `B→A`가 둘 다 있고 마디가 2~4개 → 기둥과 화살표
- 마디마다 한 번씩만 지나는 사슬 → 세로 트렁크
- 그 밖, 또는 마디 5개 초과 → **지금 그리던 대로** (섣불리 그리지 않는다)

93%(68/73)가 새 그림을 받고, 나머지는 오늘과 같다. 회귀가 아니다.

## Codex가 잡은 것 — 고치기 전에는 본선에 못 올린다

외부 모델을 독립 평가자로 세운 값을 했다. 아래는 전부 파일·줄이 짚힌 것이고, 채택 작업에서 하나씩 닫는다.

**FlowProto는 지금 상태로 `flow`를 대체하면 의미가 깨진다.** 이름이 같은 마디를 하나로 합친다(`FlowProto.tsx:76`, `:85`). 3-way handshake를 넣으면 "클라이언트에서 2갈래로 나뉜다"로 읽힌다. 시간 순서가 분기 그래프가 된다. → **합치기를 끄고 순서를 보존해야 한다.**

**RatioProto는 크래시한다.**

- `NaN`이 하나 있으면 `values.indexOf(max)`가 `-1`이 되고 `biggest.name`에서 죽는다(`:128`, `:151`, `:164`)
- `1e-300`과 `1e300`이 같이 오면 칸 수가 무한대가 되어 `Array.from`이 `RangeError`(`:143`)
- 0이나 음수가 있으면 **조용히** 선형으로 바뀐다(`:127`). 음수는 값만 보이고 막대는 0폭(`:231`)
→ 파서에서 `Number.isFinite(v) && v > 0`을 강제한다. 컴포넌트의 조용한 폴백에 맡기지 않는다.

**LayersProto의 `Encapsulation`은 색으로만 말한다.** "새로 붙인 칸"이 색만 다르고(`:351`), 대체 텍스트는 "진한 색이 새것"이라고만 한다(`:373`). 어느 행의 어느 칸이 새것인지 낭독기가 알 수 없다. 게다가 헤더가 전부 `shrink-0`이라 계층이 길어지면 알맹이가 0폭까지 눌린 뒤 잘린다(`:340`). 가로 스크롤은 안 나지만 정보가 사라진다. → **다시 설계.**

**빗금 색에 `var(--line)`을 직접 쓴다**(`LayersProto.tsx:125`). "`--color-*`만" 제약을 글자대로 보면 위반이다. → `border-line` 계열로 바꾼다.

**시안 넷이 `parseInline`을 안 부른다.** 기존 `StackDiagram`은 부른다(`Diagram.tsx:347`). 저장된 본문을 물리면 `**굵게**`와 백틱이 글자 그대로 보인다. → 채택 시 반드시 붙인다.

**SeqProto의 숨긴 문장도 마크업을 안 푼다**(`:248`). 낭독기가 `**같은 키**`를 그대로 읽는다. 접근성이 있는 척만 하는 자리다.

**StateProto는 없는 뜻을 만든다.** 첫 상태를 자동으로 `시작`, 나가는 길이 없으면 `끝`으로 표시한다(`:167`). 입력이 전이 일부만 설명하면 틀린 배지가 붙는다. `↑`도 사이클 분석이 아니라 목록 색인 비교다(`:124`). → 보류 판정의 근거 하나.

**SeqProto의 재시도 자동 추론이 너무 넓다**(`:176`). 앞에 같은 방향 메시지가 있고 그 사이 실패가 하나라도 있으면 이후 전부를 재시도로 본다. 관련 없는 실패를 오탐한다. → **자동 추론을 뺀다.** 라벨에 "다시"가 있으면 이미 뜻이 전해진다.

## `state`를 보류하는 이유

저장분에 `:::state`가 **딱 1편**이다. 렌더러도 파서도 있는데 아무도 안 쓴다. 여기서 갈림길이 둘이다.

1. 렌더러를 고친다 → 1편이 좋아진다
2. 프롬프트를 고쳐 모델이 쓰게 한다 → 새로 만드는 것부터 늘어난다

1은 값이 거의 없고, 2는 도식 채택이 아니라 프롬프트 작업이다. **StateProto가 없는 뜻을 만드는 문제까지 겹치므로 지금은 손대지 않는다.** B단계에서 새 질문을 대량으로 만들 때 다시 본다.

## `:::ratio`만 새 종류인 이유

표 136편이 가장 큰 덩어리인데 **렌더러 교체로는 하나도 안 좋아진다.** 표를 다른 그림으로 바꾸려면 본문이 달라져야 하고, 그러려면 문법과 프롬프트가 있어야 한다.

문법은 둘째 칸이 숫자여야 하는 것으로 잠근다. `stack`이 도피처가 됐던 것(56개 중 41% 오형)은 `parseStack`이 무엇이든 받았기 때문이다. 숫자 자물쇠는 그 도피처를 막는다. Codex 제안대로 모드(`compare|parts`)와 `unit`을 필수로 더한다.

## 하위호환

파서에 **종류를 더하기만** 하면 저장된 277편은 안 깨진다. 위험한 것은 기존 종류의 렌더러 교체이고, 그래서 위처럼 **모양을 보고 고르는** 방식을 쓴다. 못 알아본 모양은 지금 그리던 대로 둔다.

`memory`·`stack`을 별칭으로 남기고 화면만 바꾸자는 제안(`proto-layers.md:26`)은 **거부한다.** `stack` 64개가 전부 계층인지 확인되지 않았고, `MemoryMap`의 핵심 표현인 빈 공간 데이터가 저장분에 없다.
