스레드를 늘려도 CPU 병렬성이 없는 이유는?

언어 · 런타임 · python 기초 동시성

핵심

CPython 기본 빌드에서는 같은 인터프리터에 속한 스레드 하나만 한 시점에 파이썬 바이트코드를 실행한다. CPU 연산 스레드를 늘리면 GIL 경합과 전환 비용만 커질 수 있다.

셋을 띄워도 한 칸에 하나만 돈다. 코어가 넉넉해도 마찬가지다. 늘린 만큼 기다리는 줄만 길어진다.

대기하는 많은 I/O 호출과 일부 네이티브 확장은 GIL을 놓는다. 그래서 네트워크 작업이나 GIL을 해제하는 수치 연산은 스레드로도 겹쳐 실행할 수 있다.

멀티프로세스는 CPU 병렬성을 얻지만 메모리와 직렬화 비용을 낸다. GIL도 복합 연산의 논리적 경쟁까지 막지 않으므로 공유 상태는 따로 동기화해야 한다.

미리보기 — 새 문법 도입 시

CPU 연산을 늘리려면 스레드가 아니라 프로세스를 늘려야 한다. multiprocessing은 인터프리터를 따로 띄우므로 GIL 경합이 없다.

핵심 정리

I/O 대기는 스레드로 겹치고, CPU 연산은 프로세스로 나눈다.

주의

GIL은 list.append 같은 단일 연산만 지켜 준다. 읽고 고쳐 쓰는 복합 연산은 따로 잠가야 한다.

각주 — 현행에서 바꾼 값

  • ④ 배경 층 페이지 --surface → 해설 카드 --raised(테두리 --line, 반지름 14px, 안쪽 여백 20/18px) → 도식·표 카드 --surface. 층이 뒤집혀 자료 블록이 페이지에 박힌 것처럼 보인다. 새 색은 하나도 안 썼다.
  • ① 핵심 카드 본문 16px → 17px, 행간 1.7, 바탕 --accent-soft. 라벨 "핵심"은 11px/700/자간 0.06em, 색 --accent — accent-soft 위 4.65:1로 AA 4.5:1을 0.15 차이로 넘는다. 본문 글자는 --ink라 15.2:1. 아이콘은 안 붙였다.
  • ① 카드 테두리 #cfe6e1은 accent-soft를 한 단 낮춘 같은 계열 값이다. 글자를 얹는 자리가 아니라 테두리 전용이라 대비 기준(3:1, 비텍스트)에 걸리지 않는다 — accent-soft 대비 1.16:1이라 경계만 겨우 보이는 정도로 의도한 것이다. 더 또렷하게 하려면 --line으로 바꾸면 된다.
  • ② 캡션 11px --faint #666d77, 바탕은 도식 카드의 --surface → 4.78:1, AA 통과. 캡션 글("도식 · 시간 흐름", "비교표 · 기준별")은 지어낸 문장이 아니라 블록 종류에서 나오는 UI 라벨이다. :::timeline·표 블록을 그리는 자리에서 붙이면 되므로 저장된 본문은 안 고친다.
  • ③ 표 카드화 접힌 각 줄이 제 테두리(--line, 반지름 8px, 바탕 --raised)를 갖고 줄 사이는 구분선 대신 8px 틈으로 나뉜다. 기준 칸은 600 굵기 + 아래 구분선. data-label 이름표 구조는 현행 그대로라 접근성(role 유지)도 그대로다.
  • 인라인 코드 글자색 --accent (4.65:1). 차분형과 같은 값이라 두 시안이 이 항목에서는 갈리지 않는다.
  • 미리보기 ==하이라이트==는 카드 안이라 통칠(accent-soft, 반지름 3px)해도 줄이 안 무겁다. :::note·:::warn은 핵심 카드와 같은 낱장 문법(테두리 + 라벨 줄). warn 라벨 5.07:1, 본문 ink on warn-soft 14.7:1.
  • 안 바꾼 것 헤더·제목 24px·메타줄·꼬리질문·자유 입력·본문 16px·행간 1.8·문단 여백 1.15em·표 접힘 규칙.
  • 주의 카드 안에 카드가 들어가는 구조라 좌우 여백이 두 번 붙는다(해설 카드 18px + 도식 카드 12px = 한쪽 30px). 390px에서 도식 표의 폭이 현행 350px에서 290px로 60px 좁아진다 — 적용 전에 :::timeline 3주체 케이스를 실기기에서 재봐야 한다.
