스레드를 늘려도 CPU 병렬성이 없는 이유는?

언어 · 런타임 · python 기초 동시성

CPython 기본 빌드에서는 같은 인터프리터에 속한 스레드 하나만 한 시점에 파이썬 바이트코드를 실행한다. CPU 연산 스레드를 늘리면 GIL 경합과 전환 비용만 커질 수 있다.

셋을 띄워도 한 칸에 하나만 돈다. 코어가 넉넉해도 마찬가지다. 늘린 만큼 기다리는 줄만 길어진다.

대기하는 많은 I/O 호출과 일부 네이티브 확장은 GIL을 놓는다. 그래서 네트워크 작업이나 GIL을 해제하는 수치 연산은 스레드로도 겹쳐 실행할 수 있다.

멀티프로세스는 CPU 병렬성을 얻지만 메모리와 직렬화 비용을 낸다. GIL도 복합 연산의 논리적 경쟁까지 막지 않으므로 공유 상태는 따로 동기화해야 한다.

미리보기 — 새 문법 도입 시

CPU 연산을 늘리려면 스레드가 아니라 프로세스를 늘려야 한다. multiprocessing은 인터프리터를 따로 띄우므로 GIL 경합이 없다.

핵심 정리

I/O 대기는 스레드로 겹치고, CPU 연산은 프로세스로 나눈다.

주의

GIL은 list.append 같은 단일 연산만 지켜 준다. 읽고 고쳐 쓰는 복합 연산은 따로 잠가야 한다.

각주 — 기준선이 쓰는 값

  • 본문 16px / 행간 1.8 / 문단 아래 여백 1.15em. sm:(≥640px)에서 17px로 커지지만 이 시안은 390px 값으로 못박았다.
  • 인라인 코드 0.88em mono, 바탕 --accent-soft #e9f4f2, 글자색은 본문 상속 --ink #191c20 → 대비 15.2:1.
  • 메타줄·측량값 --faint #666d77 11~13px. surface 위 4.78:1, raised 위 5.23:1 — 둘 다 AA 4.5:1 통과.
  • 비교표는 390px에서 .rtable 규칙으로 줄 단위 카드로 접힌다. 머리글 줄은 display:none이 되고 data-label이 이름표로 붙는다.
  • 도식(:::timeline)은 <table>로 그려지고 칸은 --accent-soft 알약이다. 테두리 --line, 반지름 8px, 바탕 --raised.
  • 용어 링크는 본문 단위 첫 등장에만 붙는다(linkify.ts). 이 본문에서는 스레드·직렬화 둘. 표·도식 안에는 구조적으로 닿지 않는다.
  • 미리보기 구역의 문장·꼬리질문 이미 파인 길 표시는 UI 상태 예시다. 저장된 본문에는 없다.
