# cs-question-tree

CS 면접 질문을 매일 하나씩 받고 꼬리질문을 무한히 파고드는 학습 서비스.

카톡방에 올라오는 질문이 선형 텍스트라 꼬리질문의 관계가 보이지 않는다는 문제에서 출발했다. 질문을 그래프로 저장하고 사용자가 파고든 경로를 트리로 보여준다.

## 현재 상태

**계획 1(확장 엔진)과 계획 2(읽기 UI) 구현 완료.** 브라우저에서 질문을 읽고 파고들 수 있다.

| 항목 | 상태 |
|---|---|
| 지식 그래프 스키마 | 완료 |
| 정규화 게이트 | 완료 (실호출 미검증) |
| 캐시 조회 · alias 버전 관리 | 완료 |
| single-flight 생성 리스 | 완료 |
| 할당량 예약·확정·반환 | 완료 |
| `POST /api/expand` | 완료 |
| 주제어 시드 206개 · 예시 루트 8개 | 완료 |
| 홈 · 읽기 뷰 | 완료 |
| 상시 미니맵 · 지도 모드 | 완료 |
| 데스크톱 읽기·지도 2단 배치 | 미구현 |
| 해설 스트리밍 | 미구현 |
| 인증 · 경로 영속 · 매일 발행 | 계획 3 |

테스트 191개 통과, 타입체크 통과, 프로덕션 빌드 통과.

## 실행

```bash
npm install
npm run dev       # http://localhost:3000
npm test          # 191 tests
npx tsc --noEmit  # 타입체크
```

DB는 PGlite(WASM Postgres)로 인메모리에서 돈다. **Docker가 필요 없다.**

부팅 시 예시 루트 8개가 자동으로 시드된다. 노드 ID는 질문 텍스트에서 파생하므로
서버를 다시 띄워도 같은 URL이 살아 있다.

`GOOGLE_GENERATIVE_AI_API_KEY`가 없으면 결정론적 스텁이 대신 답한다. 해설 첫 문단에
개발용임이 박혀 있다. 키가 있으면 스텁은 아예 로드되지 않는다.

## 설계 핵심

**노드는 개념, 경로는 개인의 것이다.**

`qnode`의 유일키는 질문 텍스트 해시이고 부모와 무관하다. 그래서 "TCP 3-way handshake란?"은 세상에 하나만 존재하고 DB 경로와 네트워크 경로 양쪽에서 도달한다. 부모-자식 관계는 `qedge`에 따로 있다.

**전역 그래프는 DAG가 아니다.** 순환을 허용한다. 지식 관계에서는 `TCP → 3-way handshake`와 그 역이 둘 다 성립한다. 조상 중복은 경로를 만들 때만 막는다.

**정규화 게이트가 캐시의 급소다.** LLM이 자유 입력을 표준 문장으로 다듬고 그 해시가 캐시 키가 된다. 표현이 달라도 같은 노드로 수렴해야 캐시가 작동한다.

`identity_scope`가 오병합을 막는다. "락은 언제 해제되는가?"는 `java` / `os` / `postgres`에서 서로 다른 질문이다. **잘못 나눈 노드는 나중에 합칠 수 있지만 잘못 합친 노드는 복구되지 않는다.** 그래서 게이트는 확신이 없으면 더 좁은 스코프를 고른다.

**캐시 히트는 생성 LLM을 0회 호출한다.** 다만 정규화 게이트는 여전히 호출된다. "히트 = LLM 0회"가 아니라 "히트 = 생성 LLM 0회"다. 그래서 할당량과 별개로 요청 빈도 제한이 필요하다.

**경로는 노드 참조가 아니라 발자국(occurrence)으로 저장한다.** 전역 간선이 `A→C`와 `B→C`일 때 방문 집합 `{A,B,C}`에서 부분그래프를 유도하면 가본 적 없는 `B→C`가 화면에 그려진다. 부모를 명시적으로 들고 있어야 경로가 유일하게 복원된다. 계획 2는 익명 전용이라 이 구조를 클라이언트 `sessionStorage`에 둔다.

**미니맵은 상시 노출이고 접을 수 없다.** 포커스 뷰만 있으면 결국 선형이라 카톡과 구조적으로 같은 계열이 된다. 관계가 보인다는 것이 매 화면에서 체감되어야 한다.

## 알려진 한계

- **동시성이 실제로 검증되지 않았다.** PGlite는 단일 연결이라 `for update` 행 잠금과 `on conflict` 경합이 재현되지 않는다. 통과한 테스트는 순차 정합성만 증명한다. 실제 Postgres에서 재검증이 필요하다
- **LLM 실호출이 검증되지 않았다.** `GOOGLE_GENERATIVE_AI_API_KEY`가 없어 게이트와 생성은 주입한 스텁으로만 테스트했다. 프롬프트 품질과 구조화 출력 준수는 미확인
- **Gemini 실제 한도가 미확인이다.** 공식 문서가 RPM/RPD 표를 내리고 AI Studio 콘솔로 안내한다. 비용 계산의 전제가 아직 추정치다
- 주제어 시드가 206개다. 목표는 400개
- **화면 렌더링에 자동 테스트가 없다.** 로직(경로 상태·레이아웃·에러 매핑·인라인 파싱)은 테스트가 있지만 컴포넌트는 브라우저 수동 검증만 했다
- **읽기 뷰 URL이 설계와 다르다.** 설계 §7은 occurrence ID를 쓰지만 익명 전용이라 서버에 occurrence가 없어 노드 ID를 쓴다. 인증이 붙는 계획 3에서 `/j/[occurrenceId]`가 이 역할을 가져간다
- **해설 스트리밍이 없다.** 설계는 스트리밍으로 대기를 읽기 시간으로 바꾸라고 하지만 `POST /api/expand`가 JSON 통짜 응답이다. 지금은 진행 표시로 대체한다
