# CS 길라잡이

**하루에 CS 면접 질문 하나. 궁금한 곳으로 계속 파고들면, 판 만큼 지도가 남는다.**

<https://cs-pathfinder.vercel.app>

가입 없이 바로 쓴다. 지금까지 쌓인 질문은 251개.

---

## 어떤 서비스인가

매일 아침 CS 면접 질문이 하나 올라온다. 읽고 나면 아래에 **꼬리질문 다섯 개**가 붙어 있다. 궁금한 것을 누르면 그 질문의 해설이 새로 열리고, 거기서 또 다섯 갈래가 생긴다.

읽기만 하는 서비스가 아니라 **파고드는** 서비스다. 어디로 팔지는 매번 직접 고른다. 그렇게 판 경로가 그대로 내 지도로 남고, 링크 하나로 남과 나눌 수 있다.

## 화면 넷

| 화면 | 주소 | 하는 일 |
|---|---|---|
| **오늘의 질문** | `/` | 오늘 올라온 질문. 지난 질문과 남들이 판 트리도 여기 있다 |
| **질문 화면** | `/q/…` | 해설을 읽고 꼬리질문으로 파고드는 곳. 가장 오래 머무는 화면이다 |
| **질문 목록** | `/questions` | 쌓인 질문 251개를 분야 10개로 나눠 훑는다 |
| **질문 지도** | `/map` | 질문 전부를 별자리처럼 펼쳐 서로 어떻게 이어지는지 본다 |

맨 위 헤더에서 언제든 옮겨 다닌다.

## 이렇게 쓴다

### 1. 홈에서 오늘의 질문을 연다

<img src="code/docs/screenshots/home.png" width="820" alt="홈 화면. 위쪽에 서비스 소개가 있고 그 아래 오늘의 질문 카드가 제목·요약·파고들기 버튼과 함께 크게 놓여 있다" />

가운데 큰 카드가 오늘 질문이다. `파고들기 →`를 누르면 질문 화면으로 간다. 더 아래로 내리면 지난 질문들과, 남들이 판 트리를 모아 둔 게시판이 나온다.

### 2. 해설을 읽는다

<img src="code/docs/screenshots/reading.png" width="820" alt="질문 화면 위쪽. 제목 아래 답 한 문장이 먼저 오고 그 바로 뒤에 4-way handshake가 번호 매긴 네 단계 순서 도식으로 그려져 있다" />

**첫 문장이 곧 답이다.** 배경 설명부터 시작하지 않는다. 위 화면이라면 `마지막 ACK가 유실될 수 있기 때문이다`가 첫 문장이고, 그 뒤로 근거가 이어진다. 바쁘면 첫 문장만 읽고 나가도 된다.

답 바로 뒤에 **그림**이 온다. 순서가 있는 것은 번호가 붙은 단계로, 층이 쌓인 것은 위아래로 쌓인 칸으로, 둘을 견주는 것은 표로 나온다. 줄글로 읽고 머리로 다시 그리지 않아도 되게 하려는 것이다.

화면 요소는 이렇다.

- **왼쪽 위 `← 질문 목록`** — 목록으로 돌아간다
- **그 아래 칩** — 여기까지 어떤 질문을 거쳐 왔는지. 누르면 그 질문으로 되돌아간다
- **오른쪽 위 `깊이 0`** — 몇 칸이나 파고 내려왔는지
- **맨 아래 띠** — 미니맵. 내가 판 질문이 점으로 찍힌다

### 3. 꼬리질문으로 파고든다

<img src="code/docs/screenshots/suggestions.png" width="820" alt="질문 화면 아래쪽. 꼬리질문 5개가 세로로 놓여 있고 첫 번째에 '이미 파인 길 · 바로 이동' 배지가 붙어 있다. 그 아래 직접 입력하는 칸이 있다" />

해설 아래에 꼬리질문 다섯 개가 있다. 하나를 누르면 그 질문으로 내려간다. **깊이 제한은 없다.**

- **`이미 파인 길 · 바로 이동` 배지** — 누군가 이미 판 질문이다. 새로 만들지 않고 곧바로 그 자리로 간다
- 배지가 없으면 새로 만든다. 지금은 **20~40초** 걸린다. 그동안 안내 문구가 뜨고, 오래 걸리면 문구가 바뀐다
- **`직접 물어보기`** — 다섯 개 중에 없으면 직접 적는다. 하루 몇 번까지 쓸 수 있는지 옆에 숫자로 나온다

> 적은 내용은 AI 학습에 쓰일 수 있다. 이름이나 연락처는 넣지 않는 편이 좋다.

### 4. 판 것을 확인한다

파고들수록 세 군데에 흔적이 쌓인다.

- **위쪽 경로 칩** — 걸어온 질문들과 `깊이 3` 같은 숫자
- **아래쪽 미니맵 띠** — 내가 판 점들. 점에 마우스를 올리면 질문 제목이 나온다
- **색** — 얕은 곳은 서늘한 청록, 깊어질수록 뜨거워진다. 장식이 아니라 얼마나 팠는지를 읽는 표시다

미니맵 오른쪽 `지도`를 누르면 **내가 판 것만** 전체 화면으로 펼쳐진다. 상자끼리 선으로 이어지고 지금 보고 있는 질문이 초록으로 칠해진다.

> 한 칸도 안 팠을 때는 볼 것이 거의 없다. 서너 칸 파고 나서야 쓸모가 생긴다.

### 5. 링크로 나눈다

다 판 경로는 링크가 된다. 받은 사람은 그 트리를 그대로 본다.

<img src="code/docs/screenshots/shared.png" width="820" alt="공유된 트리 화면. 분야 배지와 제목 아래로 판 질문들이 들여쓰기된 목록으로 이어지고 조회수·추천 버튼, 그리고 직접 파보라는 안내가 있다" />

목록의 각 줄이 링크라 아무 질문이나 눌러 들어갈 수 있다. 맨 아래 `나도 여기서 파보기`를 누르면 **그 트리의 첫 질문**에서 내 탐험이 시작된다. 남이 판 끝에서 이어가고 싶으면 목록의 마지막 줄을 직접 누르면 된다.

추천은 로그인 없이 눌리고 브라우저가 기억한다.

## 질문 지도 보는 법

<img src="code/docs/screenshots/map.png" width="820" alt="질문 지도. 251개 점이 분야별로 열 개 덩어리를 이루고 각 덩어리 가운데에 분야 이름과 개수가 떠 있다" />

**점 하나가 질문 하나, 색이 분야다.** 열 덩어리로 뭉쳐 있고 가운데에 분야 이름과 개수가 떠 있다.

| 하고 싶은 것 | 방법 |
|---|---|
| 질문 하나 읽기 | 점을 누른다 |
| 한 분야만 크게 보기 | 분야 이름을 누른다 |
| 제목까지 읽기 | 확대한다. 배율이 올라갈수록 점이 제목으로 바뀐다 |
| 전체로 돌아오기 | 왼쪽 아래 `⛶`(전체 보기) |
| 나가기 | 오른쪽 위 `홈으로` |

점을 누르면 아래에서 서랍이 올라온다. 해설 전문이 그대로 들어 있어 다른 화면으로 넘어가지 않고 읽는다.

<img src="code/docs/screenshots/map-sheet.png" width="820" alt="지도에서 점 하나를 누른 상태. 화면 아래 절반을 서랍이 덮고 해설이 순서 도식과 함께 펼쳐져 있다" />

서랍 아래쪽에는 **이어진 질문**이 있고, 왜 이어졌는지가 한 문장으로 붙는다.

> **JOIN 연산의 성능을 결정하는 핵심 요소는 무엇인가?**
> 이어진 질문 1개 — 조인으로 인해 성능 저하가 발생하는 원인은 무엇인가?
> *두 질문 모두 JOIN 연산 시 발생하는 성능 저하의 원인과 결정 요소를 다루고 있다.*

선은 두 종류다. **진한 선은 누군가 실제로 걸어간 길**이고, **옅은 점선은 뜻이 비슷해서 이어준 관계**다. 뒤쪽은 판정이 이은 것이라 가끔 틀린다. 그래서 다르게 그린다.

> 지도가 두 개다. 헤더의 `지도`는 서비스 전체 251개, 질문 화면 아래쪽의 `지도`는 내가 판 것만이다.

## 자주 묻는 것

**가입해야 하나요?**
아니다. 그냥 들어가서 쓴다.

**판 경로는 어디에 남나요?**
쓰는 브라우저에 남는다. 서버에 계정이 없어서 **기기를 바꾸면 사라진다.** 남기고 싶으면 링크로 공유해 두면 된다.

**질문은 누가 만드나요?**
AI가 만든다. 오늘의 질문은 매일 아침 6시에 하나 올라오고, 꼬리질문은 누를 때마다 만들어진다. 사람이 손으로 쓴 질문 30개가 기준선으로 함께 들어 있다.

**같은 질문을 두 사람이 파면 두 개가 되나요?**
아니다. 같은 것을 묻는 질문이면 이미 있는 자리로 보낸다. 그래서 `이미 파인 길` 배지가 뜬다.

**꼬리질문이 안 만들어져요.**
무료 AI 한도에 걸리면 느려지거나 실패한다. 잠시 뒤 다시 누르면 대개 된다.

**해설이 이상해요.**
AI가 쓴 글이라 가끔 틀린다. 헤더의 `문의`를 누르면 GitHub 이슈와 메일 주소가 나온다. 어느 쪽이든 좋다.

## 개발자용

```bash
cd code
npm install
npm run dev     # http://localhost:3000
```

**Docker도 API 키도 필요 없다.** `DATABASE_URL`이 없으면 인메모리 Postgres(PGlite)로 돌고, AI 키가 없으면 결정론적 스텁이 대신 답한다. 부팅할 때 질문 249개와 그 사이 관계 330개가 자동으로 들어간다.

- 어떻게 만들었는지 · 무엇을 재서 그렇게 정했는지 → [`code/docs/engineering.md`](code/docs/engineering.md)
