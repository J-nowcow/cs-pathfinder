# CS 길라잡이

**하루에 CS 면접 질문 하나. 궁금한 곳을 계속 파고들면 판 만큼 지도가 남아요.**

<https://cs-pathfinder.vercel.app>

<img src="code/docs/screenshots/home.png" width="820" alt="홈 화면. 위쪽에 서비스 소개가 있고 그 아래 오늘의 질문 카드가 제목·요약·파고들기 버튼과 함께 크게 놓여 있다" />

가입 없이 바로 쓰면 돼요. 질문 **335개**가 올라와 있고 매일 아침 6시에 하나씩 늘어요. 해설 전문은 [`cs/explanations/`](cs/explanations/)에 질문 하나에 파일 하나씩 있어서, 서비스에 안 들어오셔도 거기서 다 읽으실 수 있고요.

---

## 왜 만들었나

매일 CS 질문을 하나씩 보내 주는 카톡방에서 시작했어요. 받아 보는 건 좋았는데 늘 같은 자리에서 막혔어요. 읽다가 "그럼 이건 왜 이렇게 되지?"가 떠올라도 거기서 끝이었거든요. 다음 날이면 또 다른 질문이 왔고요.

궁금한 건 대개 **그 질문 바로 옆**에 있어요. 한 걸음만 더 들어가면 닿는데 매번 거기서 끊기는 게 아까웠어요.

그래서 꼬리를 물 수 있게 만들었어요. 해설 아래에 꼬리질문 다섯 개가 붙고, 누르면 그 질문의 해설이 새로 열려요. 거기서 또 다섯 갈래가 생기고요. **깊이 제한은 없어요.** 어디로 팔지는 매번 직접 고르시면 되고, 그렇게 판 경로가 그대로 내 지도로 남아요.

## 읽는 화면

<img src="code/docs/screenshots/reading.png" width="820" alt="질문 화면 위쪽. 제목 아래 답 한 문장이 먼저 오고 그 바로 뒤에 4-way handshake가 번호 매긴 네 단계 순서 도식으로 그려져 있다" />

**첫 문장이 곧 답이에요.** 배경 설명부터 시작하지 않아요. 위 화면이라면 `마지막 ACK가 유실될 수 있기 때문이다`가 첫 문장이에요. 바쁘시면 그것만 읽고 나가셔도 돼요.

답 바로 뒤에는 그림이 와요. 줄글로 읽고 머리로 다시 그리는 수고를 덜어 드리려고요. 순서, 상태 갈래, 계층, 메모리 배치, 시간 축, 비교표까지 내용에 따라 그리는 방식이 달라져요. 전부 사이트와 같은 색·같은 글꼴로 그려서 확대해도 안 뭉개지고 화면 낭독기도 읽어요.

넣을 게 없으면 안 넣어요. **억지로 만든 도식은 없는 것보다 나빠요.**

글에 따라 한 구절에 형광펜이 그어져 있거나 `핵심 정리`·`주의` 상자가 끼어 있기도 해요. 다 세게 칠하면 어느 것도 안 띄어서 아껴 써요.

본문에 점선이 깔린 용어(`스레드`, `TLB` 같은 것들)를 누르면 [용어 사전](https://cs-pathfinder.vercel.app/glossary)으로 가요. 25개를 한 문장씩 풀어 뒀어요.

## 파고들기

<img src="code/docs/screenshots/suggestions.png" width="820" alt="질문 화면 아래쪽. 꼬리질문 5개가 세로로 놓여 있고 첫 번째에 '이미 파인 길 · 바로 이동' 배지가 붙어 있다. 그 아래 직접 입력하는 칸이 있다" />

꼬리질문에 `이미 파인 길 · 바로 이동` 배지가 붙어 있으면 누군가 이미 판 질문이에요. 새로 만들지 않고 곧바로 그 자리로 가요. 배지가 없으면 그 자리에서 만드는데 20~40초쯤 걸려요.

다섯 개 중에 마음에 드는 게 없으면 `직접 물어보기`로 직접 적으셔도 돼요.

> 적으신 내용은 AI 학습에 쓰일 수 있어요. 이름이나 연락처는 넣지 않으시는 편이 좋아요.

해설 맨 아래에는 `이거 봤으면 이것도`가 있어요. 꼬리질문과 헷갈리기 쉬운데 성격이 달라요. 꼬리질문은 눌러서 **새로 파는** 것이고, 이쪽은 **이미 있는 질문**으로 옆걸음 하는 링크라 기다릴 필요가 없어요.

## 그 밖에

**질문 지도** — 질문 전부를 별자리처럼 펼쳐 놓고 서로 어떻게 이어지는지 봐요. 점 하나가 질문 하나, 색이 분야예요. 점을 누르면 서랍이 올라오고 해설 전문이 그대로 들어 있어요.

<img src="code/docs/screenshots/map.png" width="820" alt="질문 지도. 점 수백 개가 분야별로 열 개 덩어리를 이루고 각 덩어리 가운데에 분야 이름과 개수가 떠 있다" />

선이 두 종류인 게 눈에 띄실 거예요. **진한 선은 누군가 실제로 걸어간 길**이고 **옅은 점선은 뜻이 비슷해서 이어 준 관계**예요. 뒤쪽은 판정이 이은 쪽이라 가끔 틀려요. 그래서 다르게 그렸어요.

**링크로 나누기** — 다 판 경로는 링크가 돼요. 받은 사람은 그 트리를 그대로 보고, 목록의 아무 줄이나 눌러 들어갈 수 있어요. 맨 아래 `나도 여기서 파보기`를 누르면 그 트리의 첫 질문에서 자기 탐험이 시작되고요. 추천은 로그인 없이 눌러요.

**내 기록** — 며칠에 몇 편 팠는지 잔디로 쌓여요. 칸을 누르면 그날 편수가 나오고, 아래에는 다음에 팔 만한 질문을 골라 줘요. 그림으로 저장해서 공유하실 수도 있어요. 그림은 브라우저 안에서 그려요.

**로그인은 선택이에요.** 안 하셔도 전부 그대로 쓰실 수 있어요. 기기를 옮겨 다니실 때만 쓸모가 있어요 — 로그인하시면 판 경로와 잔디가 계정에 모여서 폰에서 판 것과 노트북에서 판 것이 합쳐지거든요. **받는 건 이메일 하나뿐이에요.** 이름도 프로필 사진도 구글이 줘도 버려요. `계정 삭제`를 누르시면 서버에 있던 게 같이 지워지고요.

**질문 목록** — 분야 10개로 나눠 훑고, 태그 18개로 걸러 봐요. 분야는 소속이고 태그는 주제라서 축이 달라요. "뮤텍스"는 분야로는 운영체제지만 태그로는 `동시성`이에요.

**RSS와 카카오톡** — 읽기 도구에 `https://cs-pathfinder.vercel.app/rss.xml`을 넣으면 매일 아침 올라온 질문이 들어와요. 카카오톡에서 **CS 길라잡이** 채널을 친구 추가하면 봇에게 바로 물어볼 수도 있어요 — "오늘의 질문"이라고 보내면 오늘 것을 주고, 아무 CS 궁금증을 보내면 비슷한 질문의 해설을 찾아 줘요.

폰을 기준으로 만들었어요. 비교표는 좁은 화면에서 줄 단위 카드로 접혀요.

## 얼마나 믿어도 되나요

**해설 초안은 AI가 써요.** 그래서 정확도를 짐작으로 말하지 않고 재요.

표본을 떠서 다른 모델(OpenAI Codex)에 넘겨 엄격한 잣대로 대조했더니 **AI가 쓴 20편 중 15편, 사람이 쓴 11편 중 7편**에서 사실 오류가 나왔어요. 대부분 완전한 헛소리가 아니라 **조건을 뺀 단정**이었어요 — "항상", "반드시"가 실제로는 조건부인 경우요. 면접에서 그대로 말하면 되묻히는 문장들이에요.

그래서 전편을 같은 잣대로 재검했어요. 모델이 쓴 245편을 4회에 걸쳐 훑어 **오류 59건을 고쳤어요.** 회차마다 오류율이 7%에서 43%까지 갈렸고, 고친 사람이 다음 오류를 만드는 것도 세 번 확인했어요. 그래서 한 번 훑은 걸로 끝내지 않아요.

335편 중 90편은 사람이 손으로 썼어요. 30편은 AI가 따라 쓸 기준선이고, 60편은 AI가 잘 안 다루던 분야(컨테이너·합의 알고리즘 같은 것들)를 메우려고 따로 쓴 거예요.

잰 방법과 기록은 [`code/docs/audit/`](code/docs/audit/)에 있어요. **틀린 걸 찾으시면 이슈로 알려 주세요.** 이 저장소가 가장 반기는 기여예요.

## 직접 돌려보기

```bash
cd code
npm install
npm run dev     # http://localhost:3000
```

**Docker도 API 키도 필요 없어요.** `DATABASE_URL`이 없으면 인메모리 Postgres(PGlite)로 돌고, AI 키가 없으면 결정론적 스텁이 대신 답해요. 부팅할 때 질문 335개와 그 사이 관계 397개가 자동으로 들어가요.

```bash
npm test        # 1269개
npm run typecheck
```

## 구조

```
cs/       질문 전문. 코드를 안 열어도 무엇이 담겼는지 보여요
code/     앱 전부 — src·data·scripts·tests·설정
```

Next.js 16(App Router) · React 19 · Tailwind v4 · TypeScript · Postgres(Neon)/PGlite · AI SDK v6 + Gemini · better-auth · Vercel.

설계에서 중요한 건 **노드는 개념이고 경로는 개인의 것**이라는 점이에요. 같은 질문은 하나만 존재하고 여러 갈래에서 도달하는데, 내가 걸어온 길은 나만의 것으로 따로 남아요. 왜 그렇게 했고 무엇을 재서 그렇게 정했는지는 [`code/docs/engineering.md`](code/docs/engineering.md)에 적어 뒀어요.
