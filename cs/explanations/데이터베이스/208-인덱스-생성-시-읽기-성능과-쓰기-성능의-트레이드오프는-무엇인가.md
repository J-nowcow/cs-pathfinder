# 인덱스 생성 시 읽기 성능과 쓰기 성능의 트레이드오프는 무엇인가?

`#208` · 데이터베이스

조회 조건에 맞는 인덱스라야 읽기가 빨라진다. 안 맞는 것을 늘리면 읽기는 그대로인데 쓰기만 무거워진다.

| 기준 | 읽기 성능 | 쓰기 성능 |
| --- | --- | --- |
| 인덱스 수 | 많을수록 유리 | 많을수록 불리 |
| 작업 내용 | 인덱스 탐색으로 범위 좁힘 | B-Tree 구조 재구성 및 정렬 |

인덱스는 데이터의 위치를 저장한 별도의 저장소다. 데이터를 삽입하거나 수정할 때 실제 데이터 페이지와 인덱스 페이지를 모두 갱신해야 한다.

특히 삽입 시 B-Tree의 노드 분할이 발생하면 여러 페이지를 수정해야 하므로 오버헤드가 크다. 따라서 쓰기 작업이 빈번한 테이블에서는 인덱스 수를 최소화해야 한다.
