# 분산 환경에서 데이터베이스 수준의 락이 가지는 한계점과 이를 해결하기 위한 분산 락의 역할은 무엇인가?

`#11` · 데이터베이스

서버가 여러 대여도 DB가 하나면 DB 락으로 막힌다. 문제는 DB 밖이다. 캐시나 외부 API처럼 그 DB가 모르는 자원은 DB 락이 지켜 주지 않는다. 이를 해결하기 위해 모든 서버가 공유하는 외부 저장소를 통해 락을 관리하는 분산 락을 사용한다.

1. **클라이언트 → 외부 저장소** — 락 획득 요청
2. **외부 저장소 → 클라이언트** — 락 획득 성공/실패 응답
3. **클라이언트 → DB** — 데이터 수정
4. **클라이언트 → 외부 저장소** — 락 해제

DB 락은 특정 DB 인스턴스에만 유효하다. 서버가 여러 대일 때, 서로 다른 DB 서버를 사용하는 환경에서는 동시성 제어를 발견하기 어렵다.

분산 락은 Redis나 ZooKeeper 같은 별도의 저장소를 사용한다. 모든 서버가 이곳을 하나로 바라보며 락을 락 획득자로 지정해 데이터 정합성을 보완한다.

실무적으로는 락 획득 대기 시간과 만료 시간(lease)을 설정한다. 소유자가 장애로 락을 풀지 못해 남는 stale lock과 무기한 대기를 막기 위해서다. 만료된 소유자의 뒤늦은 쓰기는 fencing token으로 막는다.
