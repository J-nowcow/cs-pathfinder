# 낙관적 락을 사용할 때 데이터 충돌이 발생하면 애플리케이션 수준에서 재시도 로직을 어떻게 구현하는가?

`#13` · 데이터베이스

예외를 잡아 정해진 횟수만큼 다시 시도한다. JPA는 `OptimisticLockException`을 던지고 Spring은 이를 `ObjectOptimisticLockingFailureException`으로 바꾼다.

바로 다시 걸지는 않는다. 즉시 재시도하면 같은 충돌이 연달아 난다. 조금 기다렸다 하는 백오프를 두고 무작위 지터를 섞어 몰리는 것을 흩는다.

급소는 트랜잭션 경계다. 예외가 난 트랜잭션 안에서 루프를 돌면 영속성 컨텍스트가 롤백 전용으로 표시돼 재시도가 먹지 않는다.

그래서 재시도는 트랜잭션 바깥에서 돈다. 매 시도가 새 트랜잭션으로 시작해야 한다. @Retryable을 쓴다면 프록시를 타도록 바깥 빈에 건다.

상한은 반드시 둔다. 무한 재시도는 커넥션을 다 써 버린다. 상한을 넘기면 실패로 처리하고 큐로 넘겨 나중에 보상한다.
