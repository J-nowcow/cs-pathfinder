# 서브쿼리를 언제 조인으로 재작성해야 성능이 향상되는가?

`#293` · 데이터베이스

옵티마이저는 조인 쪽에서 더 많은 경로를 살펴본다. 서브쿼리로 두면 블록 단위로만 최적화돼 전체를 보는 기회를 놓치기 쉽다.

| 기준 | 서브쿼리 | 조인 (Join) |
| --- | --- | --- |
| 실행 방식 | 독립된 블록 또는 반복 실행 | 다양한 조인 알고리즘 선택 |
| 결과 행 수 | 원본 테이블 행 수 유지 | 관계에 따라 중복 발생 가능 |
| 최적화 범위 | 쿼리 블록 내로 제한됨 | 전역적인 실행 계획 수립 |

상관 서브쿼리는 외부 행마다 다시 도는 모양이라 느려 보인다. 다만 옵티마이저가 조인으로 펴면 한 번만 돈다. 실행 계획을 봐야 안다.

조인으로 바꿀 때는 일대다에서 행이 불어나는 것을 조심한다.

서브쿼리는 있는지만 보므로 원본 행 수가 그대로다. 단순 조인으로 바꾸면 중복이 생겨 DISTINCT나 GROUP BY를 붙여야 한다. 그러면 오히려 느려진다.

최신 옵티마이저는 서브쿼리 언네스팅 기법을 통해 내부적으로 서브쿼리를 조인으로 자동 변환하여 실행한다. 따라서 개발자가 성능 개선을 위해 수동으로 변환하기 전에, 옵티마이저의 실행 계획을 먼저 확인하고 자동 최적화가 작동하지 않는 경우에만 수동으로 변환해야 한다.
