# Redis를 활용한 분산 락 구현 시 스핀 락 방식과 Pub/Sub 방식의 성능 및 구조적 차이는 무엇인가?

`#12` · 데이터베이스

스핀 락은 풀릴 때까지 계속 두드린다. Pub/Sub은 풀렸다는 신호가 올 때까지 기다린다.

1. **클라이언트 → Redis** — 락 획득 시도
2. **Redis → 클라이언트** — 실패 (Retry loop)
3. **클라이언트 → Redis** — 락 획득 시도

위 도식은 스핀 락의 반복적인 요청으로 인한 Redis 부하를 보여준다.

스핀 락은 구현이 단순하지만, 락을 획득하지 못했을 때 계속해서 Redis에 요청을 보내므로 CPU와 네트워크 부하가 발생한다.

반면 Pub/Sub 방식은 락이 해제될 때 Redis가 알림을 보내주어 불필요한 요청을 최소화한다. 폴링은 풀렸는지 계속 두드리지만 Pub/Sub은 풀릴 때 깨운다. 경합이 심할수록 헛된 왕복이 줄어든다. 대신 구독을 관리하는 비용이 붙는다.
