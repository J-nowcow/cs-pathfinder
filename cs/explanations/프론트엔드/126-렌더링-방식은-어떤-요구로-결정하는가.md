# 렌더링 방식은 어떤 요구로 결정하는가?

`#126` · 프론트엔드

콘텐츠 갱신 주기, 개인화, 검색 노출, 서버 비용으로 결정한다. 정적 콘텐츠는 SSG, 요청별 데이터는 SSR, 앱형 상호작용은 CSR이 유리하다.

| 상황 | 방식 | 이유 |
| --- | --- | --- |
| 정적 콘텐츠 | SSG | 미리 생성 |
| 요청별 데이터 | SSR | 요청 시 생성 |
| 앱형 상호작용 | CSR | 브라우저 렌더 |

SSG는 응답이 빠르고 서버 부하가 작지만 갱신이 늦을 수 있다. SSR은 최신 데이터를 주지만 요청마다 렌더링 비용과 장애 지점이 생긴다.

CSR은 초기 자바스크립트 비용과 검색 노출을 관리해야 한다. 실제 서비스는 경로와 컴포넌트마다 방식을 섞고 캐시나 재생성으로 약점을 보완한다.
