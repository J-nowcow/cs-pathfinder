# 메모리 부족 시 어떤 프로세스부터 종료되는가?

`#88` · 모바일

사용 중인 컴포넌트가 없는 캐시 프로세스부터 종료된다. 가시성과 사용자 영향이 클수록 우선순위가 높아지고 포그라운드 프로세스는 마지막에 보호된다.

위가 위층이다.

| 층 | 설명 |
| --- | --- |
| 포그라운드 | 사용자가 현재 상호작용한다 |
| 가시 | 화면에 보이거나 인지되는 작업이다 |
| 서비스 | 시작된 서비스를 수행한다 |
| 캐시 | 활성 컴포넌트가 없다 |

프로세스 등급은 가장 중요한 활성 컴포넌트에 맞춰진다. 중요한 클라이언트가 바인드한 서비스의 프로세스도 우선순위가 올라간다.

백그라운드 프로세스의 수명을 전제로 설계하면 안 된다. 메모리의 싱글턴 값은 사라질 수 있으므로 화면과 작업을 복원 가능하게 만든다.
