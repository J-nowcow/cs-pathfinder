# 모바일 요청은 실패할 때마다 다시 보내도 되는가?

`#105` · 모바일

실패할 때마다 보내면 안 된다. 일시 오류만 제한적으로 재시도하고 쓰기 요청은 멱등성을 보장해야 한다. 영구 오류와 사용자 취소는 즉시 끝낸다.

1. **클라이언트 → 서버** — 요청과 멱등 키를 보낸다
2. **서버 → 클라이언트** — 일시 오류와 대기 정보를 돌려준다
3. **클라이언트 → 클라이언트** — 백오프와 지터로 기다린다
4. **클라이언트 → 서버** — 조건이 맞을 때만 재시도한다

타임아웃과 일부 5xx와 429는 후보가 된다. 상태 코드만 보지 말고 API 계약과 Retry-After를 따른다. 대부분의 4xx는 재시도해도 성공하지 않는다.

지수 백오프는 반복할수록 간격을 늘린다. 지터는 여러 기기가 동시에 깨어 서버를 다시 압박하는 재시도 폭주를 줄인다.

앱이 백그라운드로 가거나 연결이 바뀌면 예약을 다시 판단한다. 꼭 전달할 작업은 메모리가 아닌 영속 큐에 넣고 최대 횟수와 만료 시점을 둔다.
