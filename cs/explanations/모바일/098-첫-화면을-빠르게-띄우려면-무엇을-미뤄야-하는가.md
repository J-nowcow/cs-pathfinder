# 첫 화면을 빠르게 띄우려면 무엇을 미뤄야 하는가?

`#98` · 모바일

첫 화면에 필요 없는 초기화를 미뤄야 한다. Application과 시작 화면의 동기 작업을 줄이고 분석 도구나 캐시 예열은 지연하거나 백그라운드로 보낸다.

1. **프로세스 → Application** — 필수 초기화만 한다
2. **Application → 첫 화면** — 렌더링을 시작한다
3. **첫 화면 → 백그라운드** — 나머지를 지연 실행한다

콜드 시작은 시작 요청부터 첫 프레임까지 재며 프로세스 초기화도 포함한다. 웜 시작과 핫 시작은 재사용 자원이 달라서 같은 수치로 섞으면 병목을 잘못 판단한다.

시작 추적에서 메인 스레드의 디스크 접근과 클래스 로딩을 찾는다. Baseline Profile은 자주 쓰는 코드의 해석과 컴파일 비용을 줄인다.

지연 초기화도 사용 직전에 몰리면 끊김이 생긴다. 기능 우선순위와 의존성을 정하고 실제 기기에서 첫 표시와 완전 표시를 함께 측정한다.
