# 처리에 실패한 메시지는 어디로 가는가?

`#281` · 아키텍처 · 분산시스템

큐와 소비자 설정에 달렸다. 다시 주는 것도, 몇 번 만에 따로 둔 큐로 옮기는 것도 저절로 되는 것이 아니라 정해 두는 것이다.

1. **큐 → 소비자** — 메시지를 준다
2. **소비자 → 큐** — 처리하지 못했다고 알린다
3. **큐 → 소비자** — 잠시 기다렸다 다시 준다
4. **큐 → 실패 큐** — 횟수를 넘기면 옮긴다

**순서를 지키는 자리에서는 옮기지 않으면 줄이 막힌다.** 맨 앞이 계속 실패하면 뒤엣것이 영영 처리되지 않는다. 다만 옮기는 순간 원래 순서는 깨진다.

다시 주는 간격을 점점 늘리는 것도 정책이다. 같은 간격으로 몰아치면 이미 힘든 곳을 더 때린다.

옮긴 뒤가 진짜 일이다. 실패 큐에 쌓인 것을 아무도 안 보면 조용히 잃은 것과 같다. 쌓이면 알리도록 걸어 둔다.
