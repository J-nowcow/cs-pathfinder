# 요청을 어떤 서버로 보낼지 어떻게 정하는가?

`#151` · 네트워크

서버 성능과 요청 비용이 비슷하면 순환 분배가 단순하다. 연결 길이가 제각각이면 최소 연결을 쓴다. 세션 고정이 필요하면 일관된 해시를 고려한다.

| 상황 | 선택 | 이유 |
| --- | --- | --- |
| 균일한 요청 | 라운드 로빈 | 단순한 균등 분배 |
| 긴 연결 혼재 | 최소 연결 | 점유량 반영 |
| 노드 증감 | 일관된 해시 | 키 이동 최소화 |

가중치를 주면 성능이 다른 서버에 처리량만큼 요청을 보낼 수 있다. 정적 가중치는 실제 부하 변화를 늦게 반영한다.

최소 연결도 연결당 비용이 다르면 틀릴 수 있다. CPU와 지연을 반영하는 방식은 정확도가 높지만 측정 지연과 진동을 제어해야 한다.

알고리즘보다 먼저 비정상 노드를 제외하는 헬스 체크가 필요하다. 재시도는 장애를 숨길 수 있지만 과하면 남은 서버까지 압박한다.
