# 연결 설정 왕복을 언제 줄일 수 있는가?

`#144` · 네트워크

새 TCP 연결의 상태 동기화는 생략할 수 없다. 대신 연결을 재사용하거나 재접속 정보를 활용해 애플리케이션 데이터 전송을 앞당길 수 있다.

1. **클라이언트 → 서버** — SYN. 시작 순번을 알린다
2. **서버 → 클라이언트** — SYN + ACK. 수락하고 순번을 알린다
3. **클라이언트 → 서버** — ACK. 양쪽 상태가 맞았음을 확인한다

세 단계는 양쪽의 송수신 가능 여부와 초기 순번을 확인한다. 한 단계를 없애면 지연 패킷을 새 연결로 오인하거나 반쪽 연결이 늘 수 있다.

Keep-Alive와 연결 풀은 이미 맺은 연결을 다시 쓴다. 새 핸드셰이크 자체를 줄이므로 가장 일반적인 지연 절감 수단이다.

TCP Fast Open은 쿠키가 있는 재접속에서 SYN에 데이터를 실을 수 있다. 핸드셰이크는 계속 진행되며 중간 장비 호환성과 재전송 안전성을 고려해야 한다.
