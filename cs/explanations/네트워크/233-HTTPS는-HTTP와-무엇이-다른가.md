# HTTPS는 HTTP와 무엇이 다른가?

`#233` · 네트워크

HTTP에 SSL/TLS 프로토콜을 추가해 데이터를 암호화한 것이다. 이를 통해 도청, 변조, 위조를 막는다.

| 프로토콜 | 전송 방식 |
| --- | --- |
| HTTPS | HTTP + SSL/TLS |
| HTTP | 평문 전송 |

전송 계층 위에 SSL/TLS라는 보안 계층을 얹은 구조다. 클라이언트와 서버가 서로의 신원을 확인하고 암호화 키를 교환하는 과정이 핵심이다.

대칭키로 데이터를 빠르게 암호화하고, 비대칭키로 그 대칭키를 안전하게 전달한다. 성능 저하를 최소화하면서 보안성을 챙긴 방식이다.

인증서 기관(CA)의 서명을 통해 서버가 가짜가 아님을 보증한다. 인증서가 없으면 암호화는 가능해도 상대가 누구인지 알 수 없어 피싱에 취약하다.
