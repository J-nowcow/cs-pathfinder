# TCP의 4-way handshake 과정을 3단계로 단축할 수 없는 이유는 무엇인가?

`#29` · 네트워크

양방향 연결을 각각 독립적으로 닫아야 하기 때문이다. TCP는 전이중(Full-Duplex) 통신을 지원하므로 송신과 수신 경로가 별개로 동작한다. 한쪽이 연결을 끊고자 해도 다른 한쪽은 여전히 데이터를 보내는 중일 수 있어서 두 경로를 따로 닫아야 한다.

4-way handshake는 양방향 경로를 순차적으로 정리하는 흐름을 따른다.

1. **A → B** — FIN (나 더 이상 보낼 데이터 없어)
2. **B → A** — ACK (확인했어, 하던 일 마저 보낼게)
3. **B → A** — FIN (나도 이제 더 보낼 데이터 없어)
4. **A → B** — ACK (확인했어, 정말 끝낼게)

네 단계가 되는 것은 B에게 보낼 데이터가 남았을 때다. 그때는 ACK를 먼저 보내고 FIN은 전송을 마친 뒤 보낸다. B가 곧바로 닫으면 ACK와 FIN이 한 세그먼트로 합쳐져 3단계로 끝난다. 반이중(Half-Close) 상태가 남은 데이터를 지킨다.

면접에서는 이와 관련해 소켓 API의 차이를 묻기도 한다. close()는 디스크립터를 반납해 송수신을 함께 끝내지만, shutdown()은 인자로 방향을 고른다. Half-Close는 송신만 닫는 shutdown(SHUT_WR)로 만든다.
