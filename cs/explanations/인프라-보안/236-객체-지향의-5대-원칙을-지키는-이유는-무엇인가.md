# 객체 지향의 5대 원칙을 지키는 이유는 무엇인가?

`#236` · 인프라 · 보안

변경에 유연하게 대응하여 소프트웨어의 유지보수 비용을 낮추기 때문이다.

| 기준 | 절차 지향 | 객체 지향 |
| --- | --- | --- |
| 중심 | 순서와 로직 | 데이터와 행위 |
| 변경 영향 | 연쇄적인 수정 필요 | 캡슐화된 객체만 수정 |

상속과 다형성을 통해 코드 중복을 줄인다. 인터페이스를 통해 구현체와 사용자를 분리하면, 내부 로직이 바뀌어도 호출하는 쪽은 영향을 받지 않는다.

결합도는 낮추고 응집도는 높이는 것이 핵심이다. 이를 통해 시스템이 커져도 특정 기능을 수정할 때 다른 곳에서 예상치 못한 버그가 터지는 것을 막는다.
