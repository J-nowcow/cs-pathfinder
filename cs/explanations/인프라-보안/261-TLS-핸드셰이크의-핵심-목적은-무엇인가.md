# TLS 핸드셰이크의 핵심 목적은 무엇인가?

`#261` · 인프라 · 보안

클라이언트와 서버가 서로의 신원을 확인하고, 데이터를 암호화할 수 있는 대칭키를 안전하게 공유하는 것이다.

1. **클라이언트 → 서버** — Client Hello. 지원 버전과 암호화 방식 제안
2. **서버 → 클라이언트** — Server Hello. 암호화 방식 선택 및 인증서 전달
3. **클라이언트 → 서버** — Key Exchange. 서버 신원 확인 후 프리마스터 시크릿 전달
4. **서버 → 클라이언트** — Finished. 모든 설정 완료 및 대칭키 생성

위 흐름을 통해 신뢰할 수 있는 기관(CA)이 서명한 인증서를 확인하여 중간자 공격을 방지한다. 공개키 기반의 비대칭 암호화로 초기 연결을 횃불처럼 보호한다.

최종적으로 생성된 세션 키는 대칭키 암호화 방식을 사용한다. 비대칭 암호화는 연산량이 많아 실제 데이터 전송 시에는 효율적인 대칭키를 쓰는 것이 핵심이다.

TLS 1.3 버전에서는 이 과정을 1-RTT로 줄여 연결 속도를 성능상 이득을 얻었다. 이전 버전보다 불필요한 왕복 횟수를 처음부터 줄여 지연 시간을 단축했다.
