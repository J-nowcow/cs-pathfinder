# 엔티티를 API 응답에 바로 쓰면 무엇이 새는가?

`#141` · 프레임워크

영속성 구조와 내부 필드가 외부 계약으로 샌다. 연관관계 직렬화가 지연 쿼리와 순환 참조를 만들고 엔티티 변경이 API 변경으로 번진다.

위가 위층이다.

| 층 | 설명 |
| --- | --- |
| API DTO | 외부 계약과 검증 |
| 응용 서비스 | 유스케이스 조정 |
| 도메인 엔티티 | 상태와 핵심 규칙 |
| 영속성 | 테이블과 연관관계 |

요청 DTO는 입력 형식과 검증을 맡는다. 응답 DTO는 공개할 필드와 표현을 고정한다. 엔티티는 자신의 불변식과 생명주기에 집중한다.

조회 전용 응답은 필요한 필드만 투영하면 엔티티 그래프를 만들지 않아도 된다. 이는 직렬화 중 추가 쿼리와 과도한 데이터 노출을 줄인다.

분리에는 매핑 코드와 중복 비용이 따른다. 계약이 자주 변하거나 외부에 공개될수록 가치가 크며 작은 내부 기능은 복잡도와 함께 판단한다.
